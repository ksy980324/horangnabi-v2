# 호랑나비 · horangnabi-v2

**[호랑나비 접속하기](https://ksy980324.github.io/horangnabi-v2/)** — GitHub Pages 공개 배포 완료. PC 실행 없이 휴대폰에서 접속할 수 있습니다. 기존 PC/LAN 일정은 JSON 백업·복원으로 가져오세요.

우리 둘의 여행을 위한 모바일 중심 여행 플래너입니다. 기존 프로젝트를 건드리지 않고 이 하위 폴더에 독립적으로 구현했습니다. Firebase 계정은 필요하지 않습니다. Google Maps를 사용하려면 API 키와 결제 설정이 필요하며, 키 없이 실행하면 기존 무료 지도를 표시합니다.

## Google Maps 연결
집 밖에서도 접속할 GitHub Pages 배포는 [배포 안내](docs/GITHUB_PAGES_SETUP.md)를 참고하세요. 공개 저장소는 [ksy980324/horangnabi-v2](https://github.com/ksy980324/horangnabi-v2)이며 실제 배포 상태는 [진행 상황](docs/PROGRESS.md)에 기록합니다. 무료 Pages는 소스와 앱 화면이 공개되는 방식입니다.

한국어 Google Maps와 번호 핀, 일정 연동을 구현했습니다. [Google Maps 설정 안내](docs/GOOGLE_MAPS_SETUP.md)를 따라 Google Cloud에서 Maps JavaScript API를 켜고, `.env.example`을 `.env.local`로 복사한 뒤 API 키를 입력하세요. 서버를 재시작하면 Google 지도로 전환됩니다. 배포 전에는 자체 JavaScript Map ID를 생성해 설정하세요. 장소 검색은 기존 Photon을 유지하므로 Google Places 설정은 필요하지 않습니다. API 키는 채팅에 보내지 않아도 됩니다.

## 개발 환경과 실행
휴대폰에서 같은 와이파이로 확인하려면 `npm.cmd run dev:mobile`을 실행하세요. 접속 주소·Google 키 허용 목록·방화벽·데이터 이동은 [휴대폰 접속 안내](docs/MOBILE_ACCESS.md)를 참고하세요. 외부 접속용 배포와 공동 편집은 별도 단계입니다.

Node.js 22.12 이상(또는 24 LTS)과 npm이 필요합니다. Node.js 설치 시 npm도 함께 설치됩니다. PowerShell에서:

```powershell
cd C:\Users\ct06\vscode-repos\horangnabi\horangnabi-v2
npm install
npm run dev
```

터미널에 나온 주소(기본 `http://127.0.0.1:5173`)를 브라우저에서 여세요. 종료는 터미널에서 Ctrl+C입니다. 지도 타일과 장소 검색, 웹폰트에는 인터넷이 필요하며 웹폰트 실패 시 시스템 글꼴을 사용합니다.

```powershell
npm run typecheck
npm test
npm run build
npm run preview
```

`build`는 배포 파일을 `dist`에 생성합니다. `preview`는 빌드 결과를 기본 `http://127.0.0.1:4173`에서 확인합니다. 2026-11-05 지도 언어 수정 후 TypeScript 검사·테스트 7개·프로덕션 빌드가 통과했습니다. 실제 브라우저에서의 지도 타일 표시와 모바일 조작은 별도 확인이 필요합니다. Windows PowerShell에서 스크립트 실행 정책 오류가 발생하면 `npm` 대신 `npm.cmd`를 사용하세요. Node.js 24에서는 의존성 설치 없이 기존 데이터/검색 로직 테스트를 아래처럼 실행할 수 있습니다.

```powershell
node --experimental-strip-types --test tests/data.test.ts tests/search.test.ts
```

## 사용 방법
**여행 열기 → 준비물**에서 여권·충전기처럼 챙길 것을 추가하세요. 체크하면 준비 완료로 표시되며 연필 버튼으로 이름 수정, 휴지통 버튼으로 삭제할 수 있습니다. 완료 개수와 진행률도 표시됩니다. 각 여행에 따로 저장되고 JSON 백업에도 포함됩니다. 두 기기 간 자동 동기화는 아직 지원하지 않습니다.

여행을 열고 **장소 보관함 → 후보 장소 추가**를 누르면 날짜를 정하지 않고 장소를 모아둘 수 있습니다. 검색하거나 지도에서 고르고, 장소 이름만 입력해 저장해도 됩니다. 후보 카드를 누르면 수정·삭제와 날짜 선택이 나타납니다. **일정으로 이동**하면 해당 날짜 마지막에 시간 미정 일정으로 옮겨지고 보관함에서는 빠집니다. 후보도 JSON 백업에 포함됩니다.

상단 나비 로고와 '호랑나비'를 누르면 홈으로 돌아갑니다. 새 여행의 날짜는 오늘로 채워지며 변경할 수 있습니다. 같은 공유기에서 HTTP로 접속해도 여행과 일정을 생성할 수 있습니다.

도시를 선택하면 실제 지도 위치를 확인해 여행에 저장합니다. 좌표가 연결된 여행은 일정이 없는 날에도 해당 도시를 보여 주며, 새 장소 검색도 그 도시 주변에서 시작합니다. 기존 여행은 `여행 수정`에서 도시를 다시 선택하거나 `도시 위치 다시 확인`을 누르면 연결할 수 있습니다. 동명 도시나 검색 오류로 위치를 확인하지 못하면 안내 후 위치 없이 저장할 수 있습니다. 입력 중 자동 요청은 없으며 도시 선택/위치 확인 버튼을 누를 때만 요청합니다.

1. 첫 실행에 오사카 예시 여행이 표시됩니다. 여행 카드를 누르거나 새 여행을 만드세요. 새 여행에서는 국가·지역을 고른 뒤 도시를 선택합니다. 기본 목록은 249개 국가·지역과 50개 국가의 351개 도시·여행지역(일본 75곳)이며 유명 도시와 소도시가 함께 있습니다. 도시명은 한글·영문·등록된 현지어로 검색할 수 있습니다. 기본 목록 밖은 국가별 추가 검색이나 직접 입력을 사용하세요.
2. 날짜 탭에서 하루를 선택하세요. 카드를 누르면 지도 이동과 상세 정보 표시, 핀을 누르면 카드로 스크롤합니다. 지도가 상단에 고정되어 일정을 내리면서 볼 수 있고, 읽고 있는 카드 번호에 따라 지도 위치와 강조가 바뀝니다. 스크롤만으로 상세 내용은 펼치지 않습니다.
3. `일정 추가하기`에서 장소 검색 후 결과를 누르거나 지도를 직접 누르세요. 검색 범위에서 여행지 주변 우선, 현재 지도 안, 전체 지역을 고릅니다. 장소 이름과 주소는 맨 위 검색창에 입력하세요. 결과에서 상세 주소·장소 종류·직선 거리를 확인하고 관련도순/가까운순으로 정렬하세요. 시간은 비워 둘 수 있습니다. 장소 이름만 입력해 위치 없는 일정을 저장할 수도 있습니다.
4. 카드의 위/아래 화살표로 순서를 바꾸세요. 카드를 선택하면 수정·삭제가 표시됩니다. 핀 번호와 핀 사이 가는 청록색 점선은 목록 순서를 따릅니다. 선은 실제 도로 경로가 아닌 순서 표시이며 좌표 없는 일정은 건너뜁니다. 경로 계산 API를 사용하지 않습니다.
5. 하단 `JSON 백업`으로 데이터를 내려받으세요. 다른 기기에서는 `복원`으로 가져옵니다. 복원은 기존 여행 전체를 교체합니다.

## 한국어 장소 검색

장소 추가 화면 맨 위 검색창에 장소 이름이나 Google 지도 앱에서 복사한 공유 링크를 붙여넣으세요. 링크는 붙여넣을 때 이름과 위치를 읽고, 일반 이름 검색은 검색 버튼을 눌러 실행합니다. 지도 아래에 선택한 장소와 검색 결과가 나오며 작은 검색 범위 선택창은 그 아래에 있습니다.

숙소는 여행의 **예약 → 예약 추가 → 숙소**에서 같은 방식으로 검색합니다. 숙소를 선택하고 현지 체크인·체크아웃 날짜와 시간을 입력하면 숙소 위치가 연결된 일정이 생성됩니다. 항공편명은 입력하면 영문 대문자로 바뀝니다.

공유 링크 변환 서버의 코드를 수정한 경우 GitHub push와 별도로 프로젝트 폴더에서 아래 명령으로 Cloudflare Worker도 배포하세요.

```powershell
npx.cmd wrangler deploy --config workers/maps-link/wrangler.jsonc
```

`요나고 공항`·`요나고 기타로 공항`·`YGJ`도 지원합니다. 공항을 지역 우선순위 없이 찾으려면 이름을 입력한 뒤 `공항 이름으로 전체 지역 검색`을 누르면 전체 지역에서 찾을 수 있습니다.

검색 결과는 한국어 이름을 크게, 원래 이름은 바로 아래 작고 옅게 표시합니다. 응답에 한국어 이름이 있으면 우선 사용하고, 없으면 주요 공항·명소·상점의 등록된 이름을 적용합니다. 주소도 알려진 국가·도시·구를 한국어로 표시하며 원문 주소를 아래에 보존합니다. 한국어 이름을 확보하지 못한 장소나 모르는 도로명은 원문이 남을 수 있습니다. 검색 결과 이름은 등록된 한국어 표기를 우선합니다. 검색어의 영어 재시도에는 아래의 무료 번역을 사용합니다.

한국어로 검색해 결과가 없으면 영어로 번역한 검색어로 한 번 더 찾아봅니다. 예를 들어 `돗토리역`은 `Tottori Station`으로 검색합니다. 등록된 지명은 통용 영문 표기를 쓰고, 역·공항·호텔 같은 시설명은 뜻을 번역합니다. 사용한 영어는 결과 안내에 표시합니다. 검색 범위는 유지하며 원문에서 결과가 나오면 영어 재검색을 생략합니다. 미등록 고유명사의 공식 영문 표기는 번역 결과나 발음 기반 표기와 다를 수 있습니다.

등록된 단어로 바꾸기 어려운 표현은 [MyMemory 번역 API](https://mymemory.translated.net/doc/spec.php)에 검색어만 전달합니다. 익명 무료 사용은 [일일 5,000자](https://mymemory.translated.net/doc/usagelimits.php) 한도이며 별도 키를 입력할 필요가 없습니다. 번역 실패 시 안내 후 Google 지도 검색을 사용할 수 있습니다. 검색 결과의 정확한 장소 종류와 주소도 확인하세요.

## 저장 주의사항

현재 데이터는 해당 주소의 해당 브라우저 localStorage에만 저장됩니다. 주소/포트/브라우저가 바뀌면 별도 저장소입니다. 브라우저 데이터 삭제나 기기 변경 전에 JSON 백업을 보관하세요. 저장 공간 부족·차단은 화면에서 안내합니다. 손상된 저장 데이터는 자동으로 덮어쓰지 않습니다. 오사카 예시는 저장 키가 없는 첫 실행에만 생성됩니다.

현재 실시간 공동 편집은 없습니다. 두 기기에서 각각 수정한 백업을 자동 합치지 않습니다. 날짜 범위를 줄일 때 기존 일정이 제외되면 먼저 일정을 다른 날짜로 이동하거나 삭제해야 합니다. 일정 순서는 시간과 독립적으로 수동 관리합니다.

## 지도와 검색
- 키 설정 시 [Google Maps JavaScript API](https://developers.google.com/maps/documentation/javascript)를 사용하며 한국어 표시를 요청합니다. 로고 및 저작권은 SDK가 표시합니다. 지도 로드 과금과 월 무료량이 있으므로 [설정 안내](docs/GOOGLE_MAPS_SETUP.md)를 확인하세요. 키가 없으면 [MapLibre GL JS](https://maplibre.org/) + [OpenFreeMap](https://openfreemap.org/quick_start/)으로 실행하며 지도 저작권 표시를 유지합니다.
- [Photon 사용 정책 및 API](https://github.com/komoot/photon): 소규모 요청을 허용하는 공용 데모 서버입니다. 검색 버튼 제출만 요청하며 최소 2초 간격·동시 호출 방지·세션 캐시·12초 타임아웃을 적용했습니다. 가용성 보장이 없고 과도한 사용은 제한됩니다. 2인 개인 사용을 전제로 합니다. 확장 시 전용 서버나 다른 제공자로 교체하세요(`src/services/search.ts`).
- Google 지도는 한국어로 요청하며, 번역 범위는 Google 데이터에 따릅니다. 무료 지도는 한국어 → 영어 → 원래 스타일 순으로 표시합니다. 한국어 이름 속성(`name:ko`, `name_ko`)과 영어 이름 속성(`name:en`, `name_en`)을 지원하며, 번역이 없는 장소는 현지어가 남을 수 있습니다. 검색은 영문·현지어 이름이 더 잘 나올 수 있습니다(예: `Osaka Castle`). 검색어는 Photon에, 지도 요청은 선택한 지도 제공자에게 전달됩니다.
- 검색 결과는 OpenStreetMap 데이터 기반이며 영업 여부·정확성은 보장하지 않습니다. 경로 계산 및 자동 이동 시간 기능은 없습니다.

## GitHub Pages
main push 또는 수동 실행 시 GitHub Actions가 설치 → 검사/테스트 → 지도 설정 확인 → 빌드 → dist 업로드 → Pages 배포를 진행합니다. 저장소 경로는 Pages 메타데이터에 맞춰 설정합니다. 지도 Secret/Variable 등록 후 실제 공개 배포와 접속을 확인했습니다. [배포 안내](docs/GITHUB_PAGES_SETUP.md)를 참고하세요. localStorage 여행 데이터는 서버로 자동 업로드되지 않습니다.
