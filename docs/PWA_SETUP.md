# 홈 화면에 호랑나비 설치하기

기존 웹사이트를 나비 아이콘으로 여는 PWA 방식이다. 앱스토어 등록이나 새 유료 API는 필요 없다. 기존 지도·Firebase 사용량과 공유 여행 권한은 그대로 적용된다.

## 설치

이번 변경을 공개 사이트에 배포한 뒤 HTTPS 주소를 연다.

- Android: Chrome에서 호랑나비 오른쪽 상단 메뉴 → **홈 화면에 설치**. 설치 창이 없으면 Chrome 메뉴 → **앱 설치** 또는 **홈 화면에 추가**를 선택한다.
- iPhone/iPad: Safari에서 공유 → **홈 화면에 추가** → **추가**. 앱의 상단 메뉴에서도 안내를 볼 수 있다.
- PC: Chrome/Edge 주소창의 설치 아이콘 또는 호랑나비의 설치 메뉴를 사용한다.
- 카카오톡 등 앱 안에서 열었다면 Safari/Chrome으로 다시 연다. 브라우저에 따라 메뉴 이름이 다를 수 있다.

설치한 화면에서는 Google 로그인이 다시 필요할 수 있다. 같은 계정으로 로그인하면 기존 공유 여행을 불러온다. 설치가 새로운 접근 권한을 부여하지는 않는다.

## 오프라인과 업데이트

여행 상세의 오른쪽 상단 메뉴에서 **오프라인용으로 저장**을 먼저 누른다. 인터넷 없이 첫 화면을 열면 읽기 전용 일정으로 이동한다. 저장한 여행이 없으면 안내를 표시한다. 여행이 바뀌면 **오프라인 사본 갱신**을 사용한다.

사본은 한 여행의 일정과 예약 시간·장소다. 지도·사진·검색·공동 편집은 인터넷이 필요하다. 설치 후 브라우저 저장 공간이 달라진 기기에서는 사본을 다시 저장한다. 공유 계정 로그아웃 시 해당 기기의 공유 사본을 지운다.

새 버전이 준비되면 상단 메뉴의 **새 버전 적용**을 사용한다. 작성 중인 내용을 저장한 뒤 적용한다. 작성 화면이나 다른 탭을 자동 새로고침하지 않는다.

## 개발과 검증

```powershell
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd run preview
```

설치 지원은 프로덕션 빌드에서 활성화한다. 개발 서버에서는 서비스 워커를 자동 등록하지 않는다. 휴대폰 검증은 HTTPS 배포 주소에서 진행한다. 일반 LAN HTTP 주소는 설치 검증용이 아니다.

manifest의 id·start_url·scope·아이콘은 상대 경로로 두어 GitHub Pages 하위 경로를 지원한다. 빌드가 offline-worker.js에 첫 실행 코드·스타일·설치 파일 목록과 버전을 넣는다. 큰 지도/Firebase 코드는 사용한 뒤 캐시한다. 인증·Firestore·지도·검색·사진 응답은 캐시하지 않는다. 기존 오프라인 사본과 다른 앱의 캐시를 보존하고 이전 앱 버전 하나를 유지한다. 설치만으로 로그인·서버 응답이 빨라지는 것은 아니다.

PNG 아이콘을 다시 만들 때는 Windows에서 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/generate-pwa-icons.ps1`을 실행할 수 있다. 이 명령은 해당 스크립트에만 적용되며 시스템 실행 정책을 바꾸지 않는다. 일반 개발·빌드는 저장소에 포함된 PNG를 사용하므로 이 과정이 필요 없다.

실제 휴대폰 설치·Google 로그인·공동 편집 검증 범위는 PROGRESS.md에 구분해 기록한다. 스토어 배포·푸시 알림·오프라인 쓰기는 이번 범위에 포함하지 않는다.
