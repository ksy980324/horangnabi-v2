# 개발 진행 상황

최종 갱신: 2026-11-22

## 현재 구현

### 중단 작업 재개 및 재검증 (2026-11-22)
- 후속 배포: Firebase 콘솔에서 사진 문서 권한 규칙을 게시했다. 연결된 GitHub 계정으로 코드를 올렸으며, 첫 CI에서 Node 직접 실행에 필요한 `.ts` 확장자 누락을 확인해 보완했다. 후속 CI와 Pages 반영 결과를 확인한다.
- 사진 별도 저장 작업을 이어서 확인했다. 현재 코드에서 `npm run typecheck`, `npm test`(171개), `npm run build`가 모두 통과했다.
- `npm run test:rules`는 Firebase CLI 준비 단계에서 진행되지 않았다. 오프라인 재시도는 CLI 캐시가 없어 `ENOTCACHED`로 실패했다. Java 실행 파일도 확인되지 않아 Firestore 권한 검사를 통과했다고 판단하지 않는다.
- GitHub CLI의 기존 인증이 유효하지 않고, Git 연결도 `Could not resolve host: github.com`으로 실패했다. 서버 사진 규칙 게시·코드 push·Pages 배포·공개 화면 반영은 완료되지 않았다. 새 사진 저장 코드는 서버 규칙을 먼저 게시한 뒤 배포해야 한다.

### 후기 사진을 별도 Firestore 문서로 분리
- 여행 전체 600KiB 제한을 사진당 200KiB·여행당 100장/8MiB로 확장했다. 일정당 3장과 원본 25MB 제한은 유지하며 기존 Firestore의 sharedTrips/{tripId}/photos 문서에 압축 JPEG를 저장한다. 일정에는 사진 참조만 저장하고 기존 인라인 사진은 다음 내용 저장 때 원자적으로 이전한다. 새 Storage·과금 설정·공개 URL은 없다.
- 사진 생성/삭제와 일정 저장은 같은 revision 트랜잭션을 사용한다. 실패·충돌에는 기존 사진과 편집 내용을 보존한다. 사진 문서는 변경 불가이며 참여자만 읽고 탈퇴/제외 후 접근은 차단한다. 저장 구조 이전은 최근 변경에 별도 후기 변경으로 남기지 않는다. 일정/후기/여행 삭제 시 연결 사진을 함께 삭제하고 준비물·닉네임·초대·참여자 변경은 사진 참조를 보존한다.
- 미리보기와 블로그 사진은 필요할 때 읽고 계정/여행별 최대 100장 메모리에서만 재사용한다. JSON 백업은 모든 사진을 읽어 인라인으로 복원한 뒤 생성하고 실패 시 불완전한 파일을 만들지 않는다. 여행별 JSON 백업과 32MiB 입력 제한을 추가했다. 큰 가져오기는 원자적 요청/규칙 접근 한도 때문에 여행별로 나누어 안내하며 부분 저장하지 않는다. 블로그 ZIP은 기존 8MiB 제한과 날짜별 분할 안내를 유지한다.
- 타입 검사·자동 테스트 171개와 프로덕션 빌드를 확인했다. 참조 검증·이전·보존/삭제·600KiB 초과 저장·8MiB/100장 제한·백업 왕복·블로그/화면을 검사했다. 로컬 권한 검사는 네트워크/Java 환경 제약으로 실행하지 못했으며 배포 CI에서 새 사진 권한 검사 4개를 포함해 확인한다. 규칙 게시와 공개 화면 검증은 배포 단계에서 별도로 확인한다.

### HEIC·HEIF 후기 사진 자동 변환
- 브라우저가 직접 읽지 못하는 HEIC·HEIF 사진을 기기 안의 별도 Worker에서 해석한 뒤 기존 JPEG 압축 경로로 저장한다. 원본 사진이나 EXIF를 외부 변환 서버에 보내지 않으며 추가 API 비용은 없다. MIME이 없거나 일반 바이너리로 전달된 .heic/.heif와 시퀀스 MIME도 처리한다. 브라우저가 직접 읽는 사진은 변환기를 실행하지 않는다.
- heic-to 1.6.7의 CSP용 libheif 1.23.7 Worker를 고정한 원본에서 추출해 앱과 함께 배포한다. 첫 HEIC 대체 처리 때만 내려받으며 기존 첫 화면에 변환기를 포함하지 않는다. 성공·실패·파일 접근 오류·60초 초과 시 Worker를 종료하고 임시 URL과 큰 캔버스를 정리한다. 원본 25MB, 장당 80KiB, 일정당 3장, 여행 전체 600KiB 제한과 기존 저장·권한을 유지한다. 라이선스와 소스 위치도 함께 제공한다.
- 실제 HEVC rainbow HEIC 파일의 크기와 픽셀 해석, 손상 파일 거절, HEIC→JPEG 압축 연결, MIME/확장자 호환, 기본 브라우저 경로, 용량 제한, Worker 실패·시간 초과·재시도와 자원 정리를 검사했다. 타입 검사·전체 테스트 165개·프로덕션 빌드가 통과했다. 실제 사용자 사진과 휴대폰에서의 선택·변환은 재확인이 필요하다. 공개 반영은 배포 결과를 별도로 확인한다.

### 모바일 후기 사진 읽기 호환성 보완
- 사진의 임시 blob 주소 디코딩 실패 시 FileReader로 로컬 파일을 읽어 다시 디코딩하도록 보완했다. 각 읽기에 15초 제한과 이벤트/URL 정리를 적용하고 파일 접근 실패·해석 실패·HEIC/HEIF 미지원 안내를 구분한다. 브라우저가 지원하지 않는 HEIC를 자동 변환하는 기능은 아니며 JPG 저장/화면 캡처를 안내한다.
- 모바일 파일 제공자의 선택 파일이 처리 중 해제되지 않도록 입력란 초기화를 압축 처리 완료 뒤로 옮겼다. MIME이 없고 확장자가 확인되는 사진, image/jpg와 HEIC 시퀀스 MIME을 허용하며 파일 선택 확장자도 명시한다. 용량·개수·압축·공유 권한은 유지하고 외부로 사진을 전송하지 않는다.
- 대체 경로 성공, MIME 누락, HEIC 안내, 파일 접근 오류 및 URL 해제를 회귀 검사에 추가했다. 사용자 원본 사진이 없어 해당 사진/실제 모바일에서의 성공은 재확인이 필요하다.

### 내 후기 말투와 자연스러운 블로그 구성
- 블로그 글쓰기의 기본 문체를 내 말투 + 요즘 블로그 느낌으로 바꿨다. 선택한 후기의 끝맺음·존댓말/반말·문장 길이·어휘·유머를 우선 살리고 도입/짧은 문단/소제목/연결만 자연스럽게 다듬도록 요청한다.
- 근거 없는 유행어·광고성 과장·감탄·이모지 추가를 막고 원래 평가의 긍정/부정과 강도·사실·불확실성을 유지한다. 후기 글이 적거나 사진만 있으면 말투를 추정하지 않고 담백하고 친근하게 쓰도록 한다. 기존 친근한/정보 중심 문체 선택과 무료 자료 전달 방식은 유지한다.
- 요청문 지침과 기본 선택·기존 문체 분리를 회귀 검사에 추가했다. 실제 글은 ChatGPT에서 생성하며 문체 재현 품질은 사용자의 후기와 생성 결과에 따라 확인해야 한다.

### 추가 API 비용 없는 블로그 글쓰기 자료
- 여행 상단 블로그 글쓰기 창을 추가했다. 여행 전체/하루, 문체 두 가지, 사진 포함/제외와 계획 일정 포함을 선택하고 일정·후기 변경에 맞춰 요청문과 사진 연결을 자동 정리한다. 기본은 후기 있는 장소만 사용하며 계획은 방문 미확인으로 구분한다. 확인되지 않은 경험/가격 등을 지어내지 않는 작성 지침을 포함한다.
- 요청문 미리보기/복사와 수동 복사 대체, 사진·장소 대응 미리보기, UTF-8 요청문·연결 안내·압축 JPEG ZIP 다운로드를 제공한다. 사용자가 ChatGPT에 요청문과 사진을 직접 전달하는 방식이며 AI API·추가 과금 설정·자동 외부 전송·게시를 추가하지 않았다. 읽기 전용으로 기존 공유 저장/권한/revision/변경 기록을 유지한다. 자료 창은 뒤로가기로 닫고 PWA 업데이트를 보류한다.
- 예약·계정·가계부·교통편 메모·주소/좌표/링크/ID는 내보내지 않는다. 선택한 후기·사진 자체의 개인정보는 전달 전 확인하도록 안내한다. 파일명과 실제 사진 연결을 맞추고 빈 자료/안전하지 않은 ZIP 경로/8MiB 초과를 막는다. 추가 ZIP 라이브러리 없이 이미 압축된 사진을 저장 방식으로 묶는다.
- 타입 검사·전체 자동 테스트 160개·프로덕션 빌드가 통과했고 Windows tar와 Expand-Archive로 실제 ZIP의 한글/사진 바이트 보존을 확인했다. 날짜/일정 순서·선택 범위·후기/계획 구분·사진 매핑·개인 필드 제외·불변성·ZIP CRC32/구조·한국어/Unicode·화면 정적 렌더링을 검사했다. 실제 모바일 클립보드/다운로드와 ChatGPT 사진 첨부는 직접 검증하지 않았다. 공유 권한 검사와 공개 반영은 배포 CI로 최종 확인한다.


### 가계부 공용 하루 환율과 원화 누적 합계
- 기존 원화 누적 합계는 유지하고 환율 정책을 한국 시간 매일 오전 8시 갱신으로 변경했다. Pages 워크플로에 UTC 23시 cron과 공용 환율 파일 준비 단계를 추가해 앱이 닫혀 있어도 갱신하도록 했다. 일반 코드 배포는 당일 파일을 재사용하고 공급자 실패는 이전 조회 시각을 보존한다. 최초 적용은 한 번 초기 환율을 준비한다.
- 앱의 외부 환율 API 호출과 1분 간격 폴링을 제거했다. 공용 JSON만 읽고 공개 환율 전용 localStorage로 같은 하루 동안 재실행/새로고침에도 재사용한다. 다음 한국 08시 경계에만 확인하며 숨김/오프라인에는 중단한다. 파일 갱신 대기나 오류 때만 5분 간격으로 공용 파일을 재확인한다. 요청 타임아웃·중복 방지·저장소 오류·미래 값/손상 값 검증을 유지한다.
- 시각은 기기 시간대와 관계없이 한국 시간으로 표시하고 당일 환율의 불필요한 새로고침 버튼을 숨겼다. 지연/실패는 이전 환율과 실제 갱신 시각을 표시한다. GitHub 예약 실행과 배포에 시간이 걸리므로 8시 정각 반영은 보장하지 않는다. 지출 원본·센트 단위·최종 반올림·통화별 정산·사진/개인정보 권한은 유지한다. 공용 환율 JSON은 서비스 워커 캐시/PWA 버전 해시에 넣지 않아 환율만으로 매일 업데이트 팝업이 생기지 않게 한다.
- 환율 회귀 검사에 한국 08시 직전/정각·연말/윤일 경계, 하루 재사용/재시작, 오류/재시도/기존 값 유지, 손상/차단 저장소, 공용 파일 재사용/갱신과 공급자 실패, cron/배포 순서를 추가했다. 타입 검사·전체 테스트·Firestore 검사·빌드는 GitHub Actions에서 실행한다. 실제 휴대폰과 다음 날 예약 실행은 별도 확인 대상이다.

### 일정별 방문 후기와 사진
- 펼친 일정의 복사/수정/삭제 줄에 후기 버튼과 별도 편집창을 추가했다. 교통편 memo와 분리된 글(3,000자), 사진(일정당 3장), 사진 확대/축소·압축본 저장·개별 삭제·후기 비우기 후 저장을 지원한다. 여행 참여자가 함께 보고 수정하며 사진/글만 저장할 수도 있다.
- 사진은 원본 25MB 이내, 브라우저에서 최대 1280px JPEG로 다시 인코딩한다. 원본과 파일명/EXIF/GPS는 전송하지 않고 JPEG 문자열은 장당 80KiB·여행 전체 600KiB까지 허용한다. 기존 Firestore 문서 한도에 여유를 두어 사진이 있는 여행의 문서 추정 크기와 메타데이터 여유를 900KiB로 제한하고 초과 시 입력을 유지한다. 새 Storage/외부 API/공개 사진 URL 없이 기존 여행에 저장하므로 문서 크기·전송량은 증가한다.
- Stop.review 선택 필드와 version 1 JSON 백업을 검증한다. 일정/연결 예약 편집은 후기를 보존하며 새 일정 복사에는 후기를 옮기지 않는다. 최근 변경에는 후기·사진 필드만 기록하고 본문/이미지를 복사하지 않는다. 기존 revision·참여 권한·PWA 편집 차단을 사용하며 실패/충돌에 입력을 유지한다. 기기 모드는 저장 공간 부족 시 성공으로 처리하지 않고 편집창을 유지한다. 오프라인 읽기 사본에는 후기를 추가하지 않는다.
- 타입 검사·자동 테스트 142개·프로덕션 빌드 통과. 별도 메모 보존·사진/글 단독 저장·삭제·백업/구형 호환·유효성/여행 용량·압축 크기/품질 재시도/URL 해제·예약 갱신·복사 제외·안전한 정적 화면 렌더링을 검사했다. npm test의 IPC 소켓 제한으로 동일 전체 테스트를 node --import tsx --test tests/*.test.ts로 실행했다. Firestore 에뮬레이터 공유 권한 검사 17개도 통과했다. 사진/글 공유 수정·오래된 revision 거절·비참여자/미로그인/제거된 참여자 차단을 확인했다. 실제 모바일 사진 선택/압축/화면 조작 및 두 기기 동기화는 직접 검증하지 못했다. 개발 페이지는 브라우저에서 연결이 거절되어 시각 검증하지 못했다.


### 여행별 기념품 리스트

- 선택적인 Trip.souvenirs와 version 1 JSON 백업을 지원하고 기존 여행은 빈 목록으로 처리한다. 기존 공유 저장의 revision 충돌 검사와 실패 시 입력 유지를 사용한다. 기기 모드도 지원하고 새로고침 시 탭 복원, 편집창 뒤로가기/닫기, PWA 업데이트 보류를 기존 흐름에 연결했다. 지도는 탭 전환 시 제거하지 않는다. 최근 변경 기록에도 기념품/구매 완료/해제를 추가했다.
- 타입 검사·자동 테스트 134개·프로덕션 빌드 통과. 저장/수정·원본 보존·한도·이상 데이터·백업·중복 이름의 체크 기록·화면 정적 렌더링·탭 복원을 검사했다. npm test는 IPC 소켓 제한 때문에 동일 전체 테스트를 node --import tsx --test tests/*.test.ts로 실행했다. 공유 참여자의 추가/체크/수정/삭제와 비참여자 접근 차단 검사를 추가해 배포 CI에서 실행한다. 실제 모바일 조작/두 기기 동기화는 직접 검증하지 않았다.

### 가계부 단순 기록용과 원화 표시
- 지출 추가·수정의 구분에 단순 기록용을 추가했다. 결제자 선택은 숨기며 총지출에는 포함하고 정산에서는 제외한다. 여행 참여자 모두에게 보이고 기존 공동·개인 지출은 보존한다. 기존 필수 paidBy는 내부 호환용으로 유지하되 결제자로 표시하지 않는다. 수정 시 세 구분 간 전환을 지원한다.
- 선택적인 Expense.recordOnly boolean을 검증하고 version 1 백업·기존 공유 저장 경로를 유지한다. 단순 기록과 공동 정산이 동시에 설정된 잘못된 데이터는 거절한다. 최근 변경 내역에 구분 변경을 표시한다. 새 API·키·컬렉션·Firestore 규칙 설정은 필요 없다.
- 기존 KRW 지원을 원화라는 한국어 이름과 12,000원 표기로 명확하게 표시한다. 소수 원은 받지 않으며 환율은 변환하지 않는다.
- 타입 검사·자동 테스트 129개·프로덕션 빌드 통과. 단순 기록의 합계 포함/정산 제외·이전 참여자 영향 배제·백업 왕복·구형 데이터·잘못된 구분·KRW 정수/표시와 폼/목록 정적 렌더링을 검사했다. npm test는 환경의 IPC 소켓 제한으로 시작하지 못해 동일 전체 테스트를 node --import tsx --test tests/*.test.ts로 실행했다. 공유 통합 검사에는 단순 기록/KRW가 다른 참여자 조회와 준비물 동시 저장 후 유지되는 검증을 추가했고 배포 CI에서 실행한다. 실제 모바일 조작·두 기기 화면 동기화는 직접 검증하지 않았다.

### 여행별 최근 변경 내역
- 여행 상세 상단 최근 변경 버튼과 읽기 전용 창을 추가했다. 일정·보관함·예약·준비물·지출·여행 정보의 추가/수정/삭제/순서/이동/체크를 변경 당시 닉네임과 기기 시각으로 표시한다. 최신 50건, 저장당 최대 5개와 나머지 건수를 보관한다. 예약 자동 일정은 예약 변경으로 묶고 메모·예약 코드·금액의 이전/이후 값은 기록하지 않는다.
- 기존 공유 저장과 준비물 체크 트랜잭션에서 최신 기록을 이어 붙인다. 별도 API·쿼리·쓰기는 없고 기존 여행 문서 크기만 늘어난다. 실패·충돌·동일 내용 저장은 내역을 추가하지 않는다. version 1 백업과 호환하며 백업 가져오기는 새 여행 생성 기록으로 시작한다. 이전 전환은 원본을 보존한다.
- 기능 적용 이후의 저장부터 기록한다. 참여자/초대/닉네임 변경은 기록하지 않고 여행 삭제 시 내역도 삭제한다. 기존 참여자 권한으로만 읽는 협업 참고용이며 위변조를 막는 감사 로그는 아니다. Firebase 규칙·컬렉션·키·Worker 변경과 수동 설정은 필요 없다.
- 로컬 타입 검사·테스트 126개·프로덕션 빌드 통과. 차이 계산·순서 변경·예약 묶음·개별 체크·50건 제한·대량 요약·백업·오류 데이터를 검사했다. 동시 체크의 양쪽 기록 유지·비참여자/제거된 참여자 접근 차단 통합 검사를 추가했다. 로컬에 Java가 없어 Firestore 에뮬레이터 검사는 배포 CI에서 수행한다. 실제 모바일 UI·두 기기의 화면 동기화는 직접 검증하지 않았다.
- 첫 CI에서 동시 체크의 오래된 revision 쓰기가 ABORTED 대신 permission-denied로 거절되는 경우를 확인했다. 준비물 체크만 최신 문서를 읽어 참여 권한과 revision 증가를 확인한 경우 최대 2회 재시도한다. 정상 저장에는 추가 읽기가 없고, 경쟁 상황에서만 확인 읽기가 발생한다. 일반 일정 편집은 자동 재시도하지 않는다. 권한 제거·동일 revision·네트워크 오류·반복 실패는 우회하지 않고 중단한다.

### 추천 지도·페이지와 새로고침 복원
- 추천 창 위에 현재 페이지 번호 핀을 표시하는 Google 지도를 추가했다. 장소 이름은 지도 이동·강조, 핀은 해당 카드로 이동하며 페이지 이동에서 지도 인스턴스를 유지한다. Google 지도 키 없는 개발 환경에서는 Google 결과를 무료 대체 지도에 표시하지 않는다. 추천 창 최초 열기는 지도 로드 한 번을 사용한다.
- Google Nearby Search 한 요청에 최대 20곳을 받아 6/6/6/2곳으로 페이지를 나눈다. 페이지 이동에는 검색을 추가 호출하지 않는다. 방문한 페이지의 사진 표시 상태를 유지하고 미방문 페이지 사진/번역은 미리 요청하지 않는다. 조회 후 추가한 카드는 완료 표시로 유지한다.

- 타입 검사·테스트 119개·빌드를 통과했다. 20곳 페이지 경계, 잘못된 페이지·빈 목록, 계정/삭제 여행 격리·불량 상태·저장소 오류를 검사했다. 실제 모바일 지도·페이지 이동·Google 로그인 새로고침은 미검증이다. Firebase 권한 규칙과 기존 API 한도/카운터는 변경하지 않았다.
- Cloudflare CLI의 OAuth 인증이 만료되어 자동 갱신하지 못해 새 Worker 배포는 미완료다. Pages 배포와 별개로 docs/RECOMMENDATIONS.md의 서버 갱신 명령이 필요하다. 기존 서버는 최대 6곳을 반환하므로 새 Worker를 게시해야 다음 페이지가 표시된다.

### 추천 날짜 자동 기준과 한국어 장소명
- 추천 날짜 선택을 제거하고 조회 당시 기기 현지 날짜의 마지막 일정 위치를 사용한다. 해당 일정이 없으면 여행 도시, 없으면 여행 내 다른 위치를 사용한다. 일정 추가 대상은 기존에 열었던 여행 날짜를 유지하며 버튼에 날짜를 표시한다.
- Google 한국어 이름을 우선하고 외국어 이름은 무료 MyMemory로 번역해 원문과 함께 표시한다. 검색·사진을 먼저 보여주고 번역은 순차로 반영한다. 이름·언어만 전송하고 한 조회 내 중복 방지, 취소·시간 제한·한도/오류 시 원문 대체를 적용했다. 번역된 이름으로 추가해도 원본 지도 링크·좌표는 유지한다.
- 실제 MyMemory에서 Chinatown Bangkok → 방콕 차이나타운 응답을 확인했다. 타입 검사·테스트 116개·빌드를 통과했다. 조회일 기준·번역 언어·중복 요청·오류/한도·취소를 검사했으며 실제 모바일 UI·두 계정 동기화는 미검증이다. Google 일/월 제한·키·기존 카운터는 유지한다.

### Google 추천 서버 요청 호환성 수정
- GOOGLE_UNAVAILABLE의 직접 원인이 되는 redirect:error 사용을 찾았다. Cloudflare Workers는 이 모드를 지원하지 않아 네트워크 요청 전 TypeError를 발생시킨다. 검색·사진 메타데이터·이미지 요청을 모두 manual로 변경하고, 3xx 응답은 실패로 처리해 키를 리디렉션 대상으로 전달하지 않는다.
- 타입 검사·단위 테스트 112개·프로덕션 빌드를 통과했다. 검색과 사진 요청의 Workers 지원 모드, 3xx 응답 미추적, 이미지 호스트에 API 키 미전달을 모의 응답으로 검증했다. Google 실제 결과와 모바일 화면 검증은 사용자 재조회가 필요하다.
- 기존 API 키·프로젝트 설정·Durable Object 이름과 일/월 카운터는 변경하거나 초기화하지 않는다. 공식 근거: https://developers.cloudflare.com/workers/runtime-apis/request/

### Google 추천 장소·사진과 서버 사용량 제한
- 요나고·오사카의 고정 목록을 제거하고 전 세계 Google Places API (New) 조회로 바꿨다. 날짜·관광지/맛집/카페 선택과 명시적 버튼으로 주변 5km 최대 6곳을 인기도순 조회한다. 사진은 화면 가까이 온 카드에서 조회하며 평점·리뷰 수·주소·저작자와 출처를 표시한다.

- 기존 maps-link Worker에 인증된 추천/사진 경로와 SQLite Durable Object를 추가했다. 서버 전용 키와 Firebase 서명 토큰 검증이 필요하다. 검색·사진 각각 전체 사용자 합계 UTC 하루 25회·월 800회까지 원자적으로 선차감하며 설정/인증/카운터 실패 때 외부 API를 호출하지 않는다. 한도와 Google 오류는 일정 편집을 막지 않는다. 다른 키/프로젝트 사용·직접 호출·카운터 초기화까지 비용 0원을 보장하지 않는다.
- 타입 검사·단위 테스트 110개·프로덕션 빌드와 Wrangler 서버 패키징 dry-run을 통과했다. 모의 Google 응답, RSA 서명 토큰, 동시 제한·일/월 갱신·인증 거부·사진 전달·API 호출 전 차단을 검사했다. 실제 Google 조회·휴대폰 UI·두 계정 동기화는 미검증이다.
- Cloudflare CLI 인증이 만료되어 이 환경에서 Worker를 게시하지 못했고 서버 전용 Places 키도 아직 없다. Pages 화면 배포와 별개로 사용자 Places API 활성화→Worker secret 등록→Worker deploy가 필요하다. 명령과 비용 조건은 docs/RECOMMENDATIONS.md에 기록했다. Firestore 규칙은 변경하지 않았다.

### 새 버전 필수 업데이트 팝업
- 사용자가 PWA 설치 성공을 확인했다. 새 버전 준비 시 전역 팝업을 자동 표시하고 업데이트하기 버튼만 제공하도록 변경했다. 닫기·취소·나중에 하기·Escape/배경 닫기는 없으며, 상단 메뉴에서 선택하는 기존 업데이트 항목은 제거했다.
- 입력창, 준비물·닉네임 초안, 저장, 일정 드래그, 오프라인 사본 저장을 보호하는 차단 상태를 연결했다. 해당 작업을 마친 후에만 필수 팝업을 표시하며 여러 차단 사유가 함께 끝나야 한다. 다른 탭에서 적용해도 현재 탭의 입력을 강제 새로고침하지 않는다. 오프라인에는 팝업을 보류한다.
- 앱 복귀·연결 복구와 화면 사용 중 1분 간격으로 업데이트를 확인하며 짧은 중복 확인·숨겨진 화면·오프라인 요청은 제한한다. 적용 실패·15초 시간 초과는 재시도할 수 있고 중복 적용을 막는다. 지도 API나 새로운 유료 서비스를 호출하지 않는다.
- 타입 검사·단위 테스트 103개를 통과했다. 추가 검증은 다중 편집/저장 차단, 다른 탭 활성화, 첫 설치 구분, 오류·시간 초과·재시도, 중복 확인·배경/오프라인 제한을 확인한다. 실제 휴대폰의 새 팝업과 터치는 아직 직접 검증하지 않았다. Windows Chrome 자동 실행은 이전에 확인한 환경 제한이 남아 있다.
- 이전 설치 앱은 이번 변경을 처음 받을 때 기존 새 버전 적용 메뉴 또는 화면 재시작이 한 번 필요할 수 있다. 이후부터 필수 팝업이 동작한다. 권한·Firestore 규칙·여행 데이터 구조와 오프라인 사본은 변경하지 않았다. 소스 배포 후 공개 번들과 서비스 워커 반영을 확인한다.

### PWA 설치 기능의 PC 복원과 배포 준비
- 이전 클라우드 환경이 연결되지 않아 원본 패치를 직접 읽지 못했다. 대화에 남은 변경 내용을 기준으로 PC 저장소에 설치 메뉴·나비 PNG/SVG·manifest·서비스 워커·빌드 처리·테스트와 안내 문서를 복원했다. Windows 기본 그래픽 기능으로 PNG를 다시 만들 수 있는 선택적 스크립트를 추가했으며 일반 빌드에는 새 의존성이 없다.
- 상단 메뉴에서 브라우저 설치 창 또는 기기별 안내를 연다. 설치된 독립 화면에서는 설치 항목을 숨기고, 안내 창은 뒤로가기로 닫는다. 새 버전은 저장 안내 후 사용자가 선택해서 적용하며 작성 중인 다른 탭은 자동 새로고침하지 않는다.
- 기존 offline-worker.js 주소를 유지하고 정적 코드·스타일·설치 파일만 버전별로 캐시한다. 큰 지도·Firebase 코드는 첫 사용 후 캐시하며 인증·Firestore·지도·검색·사진 응답은 캐시하지 않는다. 기존 사본·다른 앱 캐시·이전 앱 버전 하나를 보존한다. 인터넷 없는 첫 진입은 기존 읽기 전용 사본으로 이동한다.
- 타입 검사·테스트 99개·GitHub Pages 하위 경로 빌드를 통과했다. 설치 이벤트·설치 상태·명시적 업데이트·등록 실패·캐시 범위·사본/이전 버전 보존·아이콘 크기를 검사한다. Windows Chromium 자동 검증은 실행 환경의 Crashpad 파이프 오류로 시작하지 못했으므로 브라우저 화면·실제 휴대폰 설치·Google 로그인·공동 편집은 미검증이다. 큰 지도/Firebase 번들 경고는 유지되며 권한·보안 규칙은 바꾸지 않았다.
- 이 변경은 소스·테스트·공개 아이콘·문서만 배포한다. 개인 여행 데이터나 .env.local은 업로드하지 않는다. GitHub Actions 배포 후 공개 manifest·worker·아이콘 반영을 별도로 확인한다. 설치 안내는 docs/PWA_SETUP.md에 기록했다.

### 여행 이름 자동 생성과 기기 모드 메뉴 정리
- 여행 이름을 선택 입력으로 바꾸고 미입력·공백이면 선택 도시를 사용해 도쿄 여행처럼 저장한다. 직접 지은 이름은 유지하며 좌표 없는 도시와 직접 입력한 여행지도 지원한다.
- 혼자 쓰는 여행도 계정에 저장하는 흐름으로 통일하고 상단의 이 기기의 여행 전환을 제거했다. 예전 기기 데이터가 있을 때만 하단의 이전 기기 여행 복구를 표시하며 원본 데이터와 Firebase 미설정 개발 모드는 유지한다.
- 타입 검사·테스트 91개·프로덕션 빌드를 통과했다. Auth/Firestore 에뮬레이터의 브라우저에서 도시 선택 후 이름 없이 저장, 자동 이름 표시, 기기 전환 메뉴 제거, 기존 기기 데이터 복구·보존과 계정 여행 복귀를 검증했다. 지도와 장소 검색은 테스트용 응답을 사용했다. 실제 Google 로그인·휴대폰·공개 배포는 확인하지 않았다.
- 추천 목록은 이번에 추가하지 않았다. 도시별로 앱에 포함하는 추천 목록은 별도 추천 API 요금 없이 구현할 수 있으며 Google Places 기반 조회는 별도 사용량·무료 한도·과금 항목이다.

### 닉네임 설정과 여행 참여자 표시
- Google 로그인 뒤 최초 한 번 앱용 닉네임(1~20자)을 설정한다. 기존 계정에도 적용하며 초대 링크의 목적지를 유지한다. 상단 메뉴에서 변경·취소할 수 있고 뒤로가기로 변경창을 닫는다. 계정 닉네임은 비공개 profiles 문서에 자동 저장하며 Google 계정 이름은 바꾸지 않는다.
- 여행 목록 카드에 참여자 수·닉네임 최대 3명·나 표시와 추가 인원을, 여행 상세 배너 아래에는 전체 참여자를 보여 준다. 혼자 있는 여행은 나만 보는 여행으로 구분한다. 여행 생성·초대 요청·가계부·공유 화면에 닉네임이 사용된다.
- 닉네임 변경은 모든 참여 여행의 본인 이름 필드만 부분 갱신하며 권한과 여행 내용은 보존한다. 실패 시 입력과 재시도 안내를 남기고 재접속·신규 참여 때 오래된 이름을 보완한다. 다른 사람의 비공개 프로필 조회와 이름 변조는 규칙으로 막는다.
- 타입 검사·단위 테스트 90개·Firestore 규칙 테스트 14개·빌드를 통과했다. Auth/Firestore 에뮬레이터와 격리된 브라우저 프로필에서 닉네임 필수 설정·초대 유지·카드와 상세의 동행인 표시·실시간 이름 변경·뒤로가기 취소·기존 여행 전환을 확인했다. 320·390·1280px 가로 넘침과 브라우저 예외도 확인했다. 지도는 테스트용 화면을 사용했다.
- 공개 Firebase 규칙 재게시와 Pages 배포, 실제 Google 로그인·휴대폰 동작은 아직 확인하지 않았다. 최신 firestore.rules를 게시하고 push해야 하며 profiles 컬렉션을 수동 생성할 필요는 없다.

### 여행별 초대와 참여자 권한
- Google 로그인 후 자기 여행을 만들고 여행별로 최대 20명까지 초대한다. 여행장은 7일 유효 링크 발급·취소, 참여 요청 승인·거절, 참여자 제외와 여행 삭제를 관리한다. 참여자는 공동 편집과 본인의 탈퇴를 할 수 있다.
- sharedTrips의 현재 UID가 포함된 여행만 구독하며 초대 링크만으로 일정에 접근할 수 없다. 여행별 참여자 기준으로 준비물 완료와 여러 명의 통화별 균등 정산을 처리한다. 권한 변경도 revision과 트랜잭션을 사용한다.
- 기존 두 계정의 여행은 원본을 보존하며 새 구조로 원자적으로 전환한다. 최초 전환 계정이 여행장이다. 원본의 migratedTo 표시로 중복·삭제 후 부활을 방지한다.
- 타입 검사·단위 테스트 88개·프로덕션 빌드, 실제 Firestore 에뮬레이터 보안 규칙 테스트 11개를 통과했다. 별도 브라우저 프로필 두 개와 Auth/Firestore 에뮬레이터에서 비공개 여행 생성→초대 요청→승인→일정·각자 준비물 실시간 반영→제외 후 접근 차단과 기존 여행 원본·참여자 보존·재접속 중복 없음을 확인했다. 320·390·1280px 가로 넘침과 브라우저 예외도 확인했다. 지도는 테스트용 대체 화면을 사용했다.
- 실제 Google 로그인, 공개 Firebase 규칙 게시와 Pages 배포, 실제 휴대폰 검증은 아직 수행하지 않았다. 적용 순서는 docs/FIREBASE_SETUP.md에 기록했다. 여행장 변경은 미지원이며, 공동 지출은 현재 참여자 기준이므로 참여자 변경 시 과거 지출 정산도 다시 계산된다. 다음 단계는 PWA 설치 지원이다.

### 첫 진입과 공유 여행 속도 개선
- 참여자·여행 구독을 동시에 시작하고 두 서버 응답과 참여 권한이 확인된 뒤 표시한다. 변경 문서만 재검증하고 서버 저장 확인만으로는 여행 객체를 다시 만들지 않는다. 캐시에서 받은 변경도 서버 확인 시 누락하지 않는다.
- 도시 카탈로그를 첫 화면에서 분리하고 외부 글꼴 요청을 제거했다. 첫 JavaScript gzip 크기 100,299→92,967 bytes(약 7.3% 감소). 모의 응답 지연을 고정한 브라우저 5회 중앙값은 1.36→0.95초였다. 실제 휴대폰 속도 개선율을 뜻하지 않는다.
- 타입 검사, 테스트 83개, 프로덕션 빌드와 첫 진입 용량 측정을 통과했다. 모의 공유 화면에서 권한 확인 지연·접근 거절·변경·권한 철회·캐시 변경의 서버 확인을 검증했다. 320·390·1280px 가로 넘침 없음과 도시 선택창 지연 로딩·요나고 목록 필터·뒤로가기 닫기를 확인했다. 실제 두 계정 간 동기화와 지도·검색 서버의 응답 시간은 측정하지 않았다.
- 측정 조건·제약·재실행 명령은 docs/PERFORMANCE.md에 기록했다. 후속 순서는 여행별 초대·권한 분리, PWA 설치 지원이다. 현재 공유 데이터 구조와 보안 규칙은 유지한다.

### 지도 번호 핀 크기 조정
- 지도 번호 동그라미를 기존 대비 약 75%로 축소했다. PC는 34→26px, 모바일은 36→27px이며 숫자·테두리·선택 강조도 비례해 줄였다. Google 지도와 대체 지도 모두 공통 스타일을 사용한다.
- 타입 검사, 테스트 81개, 프로덕션 빌드를 통과했다. 실제 지도 화면과 휴대폰 터치는 이번 작업에서 확인하지 않았다.

### 일정 복사
- 일정 카드를 펼친 뒤 복사를 누르면 장소·주소·좌표·사진·날짜·시간·카테고리·메모가 채워진 편집창이 열린다. 날짜와 내용을 바꾸고 복사 저장하면 선택한 날짜의 마지막 일정으로 추가되며 원본은 유지된다.
- 복사본은 새 ID를 사용하며 예약 연동은 이어받지 않는 일반 일정이다. 공유 여행의 기존 Firestore 저장·충돌 감지와 기기 여행의 localStorage 저장 경로를 그대로 사용한다. 취소·뒤로가기는 저장하지 않는다.
- 타입 검사, 테스트 81개, 프로덕션 빌드를 통과했다. 390px 브라우저에서 다른 날짜로 복사, 원본·장소 정보 유지, 뒤로가기 취소, localStorage 저장, 가로 넘침 없음을 확인했다. 지도는 모의 응답을 사용했고 실제 휴대폰 터치와 두 공유 계정의 실시간 동기화는 확인하지 않았다.

- 새 일정 지도와 주변 검색은 도시 좌표를 우선한다. 도시 좌표 없는 기존 여행은 당일 일정→전체 여행 일정 좌표 순으로 대체한다. 기존 일정 수정 시 해당 장소 좌표 우선 동작은 유지한다. 기존 여행은 여행 수정의 도시 재선택/위치 재확인으로 연결 가능하다.

- '오사카 공항'은 Osaka International Airport로 요청하며 공항(aeroway:aerodrome) 필터를 적용한다. 이타미/간사이 검색어 선택지를 제공하고, 알려진 공항 결과에는 한국어명과 원문명을 표시한다. 결과 좌표·공항 결과를 정적으로 생성하지 않으며 실제 Photon 응답을 사용한다. 같은 공항 별칭은 동일한 캐시를 사용한다.
- 결과 없음 + 지역 제한 상태에서 명시적으로 범위 제한 없이 재검색하는 버튼을 추가했다. 입력·별칭 선택 중 요청하거나 실패 시 자동 다중 검색하지 않는다. 기존 요청 간격·캐시·타임아웃·범위 검증을 유지한다.
- 실제 Chrome에서 '오사카 공항'을 입력하여 오사카 국제공항(이타미)과 간사이 국제공항 결과 및 원문/주소/거리가 표시됨을 확인했다. 5km 반경에서는 결과 없음 및 범위 확장 버튼이 표시되는 것도 확인했다.
- 범위 확장 버튼을 눌러 전체 지역으로 전환한 뒤 두 공항이 다시 표시되는 것을 실제 확인했다. 새로고침 후 Google 지도에서 가는 점선 표시와 일정 카드 선택 이동도 확인했다. 확인 과정에서는 일정을 저장하거나 기존 여행 데이터를 변경하지 않았다.
- 개발 중 지도 SDK 모듈 갱신 시 스크립트가 중복 로드되어 마커와 지도 SDK 인스턴스가 달라지는 오류를 발견했다. 로더 Promise와 실패 상태를 페이지에 보관하고 이미 로드된 SDK를 재사용하도록 수정했다.
- 수정 후 개발 모듈을 다시 갱신한 상태에서도 SDK 스크립트가 1개이고 카드 선택 시 지도가 정상 이동하는 것을 실제 브라우저에서 재확인했다. 최종 TypeScript 검사·테스트 17개·Vite 빌드 통과. 무료 지도 점선은 타입/빌드까지만 확인했으며, 실제 화면 검증은 Google 지도에서 수행했다. 실제 휴대폰 터치는 별도 확인이 필요하다.
- 별칭 보완은 제한된 공항·도시·명소 사전이며 범용 한국어 번역/Google Places 검색 품질을 보장하지 않는다. 아직 모르는 장소는 원문 검색이나 지도 직접 선택이 필요할 수 있다. 검색범위가 작으면 공항도 제외되므로 명시적인 범위 확장으로 해결한다.

### 일정 연결선과 세부 장소 검색 (2026-11-05)
- 선택 날짜의 좌표 있는 핀을 일정 순서대로 연결하는 청록색 선과 흰색 테두리를 Google Polyline 및 무료 지도 GeoJSON 레이어로 구현했다. 좌표 없는 일정은 건너뛰고 점이 0~1개이면 선을 표시하지 않는다. 날짜/순서/추가/수정/삭제 시 기존 선을 제거하고 갱신한다. 지도 아래에 실제 이동 경로가 아님을 안내한다. 경로 API는 호출하지 않는다.
- 장소 검색에 여행 일정 주변(5/20/50km), 현재 지도 안, 전체 지역과 추가 도시·상세 주소 입력을 구현했다. 추가 창은 선택 날짜의 첫 유효 좌표(없으면 여행 전체 첫 좌표)를 기준으로 시작하며, 기존 일정 수정 시 해당 장소의 좌표를 우선한다. 좌표 없는 여행은 전체 지역으로 시작한다.
- Photon 요청에 위치 편향·경계 조건을 적용하고, 응답에서도 반경 및 영역 밖 결과와 잘못된 좌표를 제외한다. 검색어·추가 주소·기준점·범위·반경별 캐시를 분리한다. 자동 검색 없이 기존 2초 간격·동시 호출 방지·12초 타임아웃·최대 100개 메모리 캐시를 유지한다.
- 결과를 최대 12개 제공하고 구/동/도로/건물 번호/우편번호가 있는 상세 주소, 종류, 기준점과의 직선 거리를 표시한다. 관련도순/가까운순 전환은 로컬에서 처리한다. 결과 선택 표시를 유지하고 지도·입력폼에 반영하며, 검색 전용 메타데이터는 일정에 저장하지 않는다.
- 실제 Chrome 모바일 화면에서 Google 지도 연결선 표시, 오사카 주변 Don Quijote + Namba 검색, 5km 반경 검색 결과, 가까운순 정렬, Nanba-Sennichimae 지점 선택 후 Google 지도 이동 및 이름/주소/좌표 입력 반영을 확인했다. 확인 과정에서 새 일정을 저장하거나 기존 일정을 변경하지 않았다.
- 현재 지도 안 검색으로 선택 지점 주변 결과 5개가 표시되는 것을 확인했다. 날짜를 2일차로 바꾸면 단일 핀만 남고 연결선이 제거되는 것도 실제 화면에서 확인했다. 무료 지도 연결선은 타입 검사와 좌표 로직 테스트까지 확인했으며 이번 브라우저에서는 Google 지도를 사용했다. 실제 휴대폰 터치는 별도 확인이 필요하다.
- 단위 테스트 14개 통과. 연결 좌표 순서/좌표 누락/역순/0좌표/범위 오류, 날짜변경선 경계, 위치·주소 쿼리, 범위 밖 동명 장소 제거, 중복·잘못된 응답 제거, 조건별 캐시 분리를 검증한다.
- 최종 TypeScript 검사와 Vite 프로덕션 빌드 성공. 기존 무료 지도 라이브러리 번들 크기 경고는 남아 있으나 해당 코드는 무료 지도 사용 시에만 동적 로드한다.
- 검색 정확도와 영업 정보는 Photon/OpenStreetMap 데이터에 의존한다. 도시·주소는 검색어를 보완하는 조건이며 모든 결과의 주소에 그 문자가 포함된다는 뜻은 아니다. 한국어 이름이 없으면 현지어/영문 또는 지도 직접 선택이 필요하다. 기준점/지도 영역 좌표도 해당 검색 요청에 포함되어 Photon에 전달된다. Google Places를 새로 사용하지 않는다.

### 고정 지도와 스크롤 연동 (2026-11-05)
- 모바일에서도 일정을 스크롤할 때 지도를 상단에 고정하고 지도 높이를 화면 높이에 맞게 제한했다. 가로 모드의 낮은 화면에서는 지도 영역을 더 줄인다. 데스크톱의 기존 고정 배치도 유지한다.
- 화면에서 읽는 카드를 계산하여 해당 번호와 위치를 지도에 반영한다. 상세 펼침 상태와 지도 강조 상태를 분리하여 스크롤 중 카드 높이 변동을 줄였다. 좌표 없는 카드는 강조만 바뀌고 지도 중심은 유지된다.
- 스크롤 처리는 requestAnimationFrame으로 묶고, 추가/수정 창이 열리면 중단한다. 핀·카드 직접 선택 및 키보드 포커스에 의한 자동 스크롤은 잠시 우선권을 가진다. 사용자 스크롤 조작 시 즉시 다시 따라간다.
- 지도 높이를 측정하여 핀 선택 후 목표 카드가 지도 아래에 보이도록 스크롤 여백을 적용했다. 새 지도 인스턴스나 별도 API 요청은 추가하지 않는다.
- TypeScript 검사·단위 테스트 11개·Vite 빌드 통과. 새 테스트는 지도 뒤에 가려진 카드 제외, 스크롤 방향, 긴 상세 카드, 낮은 화면, 마지막 카드 및 화면 밖 카드 처리를 검증한다.
- 연결된 Chrome의 모바일 화면(실측 너비 400px)에서 Google 지도 상단 고정, 스크롤에 따른 4번 장소 이동, 3번 카드 선택 시 이동, 3번 핀의 키보드 선택 후 해당 카드가 지도 아래에 노출되는 것을 확인했다. 지도 상단 8px, 카드 상단은 지도 하단보다 아래에 있었다. 가로 넘침 없음. 실제 휴대폰 터치 및 넓은 데스크톱 배치는 이번에 별도 검증하지 않았다.
- 키보드로 핀에 포커스를 옮길 때 브라우저 자동 스크롤이 다른 카드를 선택하는 문제를 브라우저 확인 중 발견하여 수정하고 재확인했다. 임시 브라우저 화면 크기 설정은 복원했다.

- `docs/FIREBASE_SETUP.md`에 프로젝트 설정, 기존 여행 가져오기, 동시 수정과 검증 절차를 정리했다. 실제 Google 계정 로그인, Firestore 규칙 검증·배포, 두 기기 동기화 확인이 남아 있다.
- 타입 검사, 테스트 40개, 빌드가 통과했다. Firebase와 OpenMap 지연 로딩 번들에 크기 경고가 있다. 현재 환경에서 Java를 찾을 수 없어 Firestore 에뮬레이터 검증은 수행하지 않았다.
- 로컬 Google 로그인 실패를 구분할 수 있도록 Firebase 오류 코드와 코드별 안내를 공유 여행 화면에 표시한다. 실제 실패 원인은 사용자 브라우저의 오류 코드 확인이 필요하다.

## 알려진 제약
- localStorage는 각 브라우저/주소에 독립적이다. 기기 간 동기화·데이터 합치기는 지원하지 않는다.
- 공용 지도 및 Photon 데모 검색 서버는 인터넷과 제공자의 가용성에 의존한다. 자동 재시도·자동완성 요청은 없다. 검색 제한은 브라우저 세션 단위이며 두 기기를 중앙에서 조율하지 않는다. 2초 이상의 간격과 소규모 개인 사용을 전제로 한다.
- 한국어 지명/장소 검색 품질은 원본 지도 데이터에 따라 다르다. 영문/현지어로 검색할 수 있다.
- 검색 캐시는 메모리에만 보관하며 새로고침 시 초기화된다.
- 여행 기간은 최대 366일. 기존 일정이 제외되는 기간 수정은 먼저 일정 이동/삭제가 필요하다.
- 이동 경로, 거리·이동 시간 계산, 자동 순서 최적화, 이미지 업로드, 여행 공유는 없다.
- 시간에 따른 자동 정렬은 하지 않는다. 카드 순서가 핀 번호의 기준이다.
- 실제 지도 및 모바일 UI 검증 후 배포하는 것이 다음 필수 단계다.
