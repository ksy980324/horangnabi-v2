# 휴대폰에서 접속하기

## 같은 공유기에서 화면 테스트

PC는 유선 연결이어도 괜찮습니다. 휴대폰을 PC와 같은 공유기의 Wi-Fi에 연결하세요. 휴대폰의 모바일 데이터나 게스트 Wi-Fi에서는 접속이 안 될 수 있습니다.

PowerShell에서 다음을 실행하고 터미널을 켜 두세요.

```powershell
cd C:\Users\ct06\vscode-repos\horangnabi\horangnabi-v2
npm.cmd run dev:mobile
```

일반 PC용 서버(5173)와 구분하려고 휴대폰 테스트는 5174 포트를 사용합니다. `Network`에 표시된 주소를 휴대폰 Safari/Chrome 주소창에 입력하세요. `localhost`와 `127.0.0.1`은 휴대폰 자신을 뜻하므로 사용하지 않습니다. `0.0.0.0`도 접속 주소가 아닙니다.

2026-11-05 확인한 PC 주소는 `http://192.168.0.16:5174/`입니다. 공유기 재연결 후에는 바뀔 수 있으므로 실행 로그의 Network 주소를 우선하세요. 포트 사용 중 오류가 나면 이전 휴대폰 테스트 서버를 Ctrl+C로 종료한 뒤 다시 실행하세요. 포트가 자동 변경되지 않도록 설정했습니다.

## 앱은 뜨는데 Google 지도만 안 보일 때

Google Cloud의 API 키 설정에서 애플리케이션 제한은 **웹사이트(HTTP 리퍼러)**로 유지하고, 다음과 같이 실제 접속 주소를 허용 목록에 추가하세요.

```text
http://192.168.0.16:5174/*
```

IP가 바뀌면 해당 항목도 갱신합니다. API 제한은 **Maps JavaScript API**로 유지하세요. 휴대폰 웹브라우저이므로 Android/iOS 앱 키 설정이나 Google Places API는 필요하지 않습니다. 설정 반영 후 새로고침하세요. 키를 채팅에 보내지 마세요.

## 접속 자체가 안 될 때

1. PC에서 같은 Network 주소를 열어 서버가 실행 중인지 확인합니다.
2. 휴대폰과 PC가 같은 공유기에 연결됐는지 확인합니다. 게스트 Wi-Fi/클라이언트 격리/VPN 환경에서는 서로 통신하지 못할 수 있습니다.
3. 신뢰하는 집 네트워크에서 Windows 방화벽 알림이 나오면 Node.js의 **개인 네트워크** 통신을 허용하세요. 방화벽 전체를 끄거나 공용 네트워크까지 허용할 필요는 없습니다. 이 설정은 사용자가 직접 확인합니다.
4. 회사·학교 네트워크 정책으로 차단되면 신뢰하는 개인 네트워크에서 테스트하세요.

개발 서버는 테스트할 때만 실행하고 Ctrl+C로 종료합니다. 공유기의 포트 포워딩으로 인터넷에 노출하지 마세요.

## 데이터 옮기기와 외부 접속

현재 일정은 주소·브라우저별 localStorage에 저장됩니다. PC의 localhost 데이터와 PC의 LAN 주소 데이터, 휴대폰 데이터는 서로 별개입니다. PC에서 **JSON 백업**을 내려받아 휴대폰으로 파일을 옮긴 후 **복원**하세요. 복원은 해당 브라우저의 여행 전체를 교체합니다. 두 사람이 각각 편집한 결과는 자동으로 합쳐지지 않습니다.

이 방식은 PC가 켜져 있고 같은 공유기에 있을 때 사용하는 테스트 방법입니다. 여행지나 모바일 데이터에서도 사용하려면 예정된 GitHub Pages 배포가 다음 단계입니다. 배포 URL을 Google 키 허용 목록에 추가하고, 빌드에 키를 공급해야 합니다. 정적 앱 배포만으로 공동 편집이 되지는 않으며 Firebase 동기화는 별도 단계입니다. 이번 작업에서는 외부 배포나 방화벽 설정을 변경하지 않습니다.

참고: [Vite 서버 설정](https://vite.dev/config/server-options), [Google Maps 키 보안 안내](https://developers.google.com/maps/api-security-best-practices).
