# 호랑나비 제품 요구사항

## 목적과 디자인
원하는 동행인끼리 여행을 함께 계획하고 편집하는 모바일 웹앱. Wanderlog의 계획 기능과 트리플의 지도·일정 사용 경험을 참고하되 독립적인 디자인과 코드를 사용한다. 무료 장기 운영, 모바일 편의성, 지도와 일정의 연동이 우선이다. 미니멀 80%와 여행 감성 20%: 흰색·연회색, 네이비 텍스트, 청록 포인트, 둥근 카드, 넉넉한 여백. 한국어 UI, 영문 파일명·식별자, UTF-8. 광고와 상품 추천을 넣지 않는다.

신규 기능은 여행별로 초대·승인된 참여자가 공유하는 흐름을 기준으로 설계한다. 여행 변경은 해당 참여자의 화면에 반영되며, 동시 편집이나 저장 실패에 대비해 기존 데이터와 사용자 입력을 보호한다. 기기에 저장된 여행은 보조 모드에서 별도로 열 수 있다.

## 최근 변경 내역

- 여행 상세 상단의 최근 변경 버튼에서 여행별 최신 50건을 최신순으로 확인한다. 변경 당시 닉네임, 저장 시각, 대상 이름, 추가/수정/삭제/순서 변경/일정으로 이동/준비 완료·해제와 변경한 필드를 표시한다. 시각은 저장 기기의 현지 시각 기준이며 서버 시각 보증은 하지 않는다.
- 일정·보관함·예약·준비물·지출·여행 정보를 기록한다. 예약에서 자동 생성된 일정은 예약 변경으로 묶고, 한 저장에서 최대 5개 변경과 나머지 건수를 표시한다. 메모·예약 코드·금액의 이전/이후 값은 복사하지 않는다. 참여자/초대/닉네임 변경은 범위 밖이며 삭제된 여행의 기록을 별도로 보관하지 않는다.
- 저장 트랜잭션의 최신 여행에서 기록을 이어 붙인다. 실패·revision 충돌·변경 없는 저장은 기록을 추가하지 않는다. 준비물 동시 체크는 재시도에서 다른 사람의 기록과 체크를 보존한다. 오래된 revision이 permission-denied로 거절되면 최신 문서의 참여 권한과 revision 증가를 확인한 경우에만 최대 2회 재시도한다. 정상 저장의 추가 읽기는 없고 이 경쟁 상황에만 확인 읽기를 사용한다. 일반 일정 편집은 자동 재시도하지 않는다. 기록을 위한 별도 조회·쓰기·외부 API 호출은 추가하지 않는다.
- 선택적인 Trip.activityLog를 사용하고 기존 version 1 백업과 호환한다. 기능 적용 전 내역은 재구성하지 않는다. 계정으로 가져온 백업은 새 여행 생성 기록부터 시작하며 기존 여행 전환은 원본을 그대로 보존한다. 기기 모드는 이 기기로 표시하고 계정 여행과 분리한다.
- 기존 참여자 권한으로만 읽는다. 일반 협업 내역이며 위변조를 방지하는 감사 로그가 아니다. 이 기능을 위해 새 컬렉션이나 보안 규칙 게시를 요구하지 않는다. 닫기·바깥 누르기·Escape·브라우저 뒤로가기로 창을 닫는다.

## 첫 번째 MVP

확장 작업은 첫 진입 성능 개선 → 여행별 초대·참여자 권한 분리 → PWA 설치 지원 순서로 진행한다. 친구가 자기 여행을 만들고 원하는 사람끼리 공유하며 기존 두 계정의 여행은 원본을 보존한 채 전환한다. PWA 설치 지원을 구현했으며 실제 휴대폰 설치 확인이 필요하다.

공유 여행은 memberIds에 현재 UID가 포함된 문서만 쿼리하고 서버 확인 후 표시한다. 전역 참여자 목록의 응답을 기다리지 않는다. 실제 변경 문서만 검증하며 캐시 변경을 서버 확인 후 누락하지 않는다. 도시 카탈로그는 편집 시 로드하고 외부 글꼴 다운로드를 요구하지 않는다. 실제 서버·휴대폰 속도와 모의 응답 실험 결과는 구분한다.

### 홈

- Firebase 설정이 있으면 공유 여행을 첫 화면으로 연다. 로그인 상태가 유지된 브라우저는 본인이 참여 중인 여행 목록을 바로 보고, 처음 방문한 브라우저는 Google 로그인 버튼을 사용한다. 기기에 저장한 여행은 별도 메뉴로 연다.
- Google 로그인 후 앱용 닉네임이 없으면 1~20자 닉네임 설정을 먼저 보여 준다. 기존 사용자도 처음 한 번 설정하며 초대 링크로 들어온 사용자는 설정 후 원래 초대 화면을 연다. 공백·제어 문자·길이 초과는 저장하지 않고 저장 실패 시 입력을 유지한다. 오른쪽 상단 메뉴에서 닉네임을 변경하며 취소·뒤로가기는 저장하지 않는다. Google 계정 이름 자체는 변경하지 않는다.
- 여행을 선택하기 전 카드 하단에 참여자 수와 닉네임을 표시한다. 혼자 있는 여행은 '나만 보는 여행', 여럿이면 'N명이 함께하는 여행'으로 표시하며 본인은 '(나)'로 구분한다. 카드에는 최대 3명과 남은 인원을, 여행 상세 배너 아래에는 전체 참여자를 표시한다. 참여자 변경과 닉네임 변경을 실시간 반영한다.
- 헤더의 호랑나비 맞은편 메뉴에서 닉네임 변경과 로그아웃을 연다. 기기 여행 전환은 일반 메뉴에서 제외한다. 과거 localStorage 데이터가 있는 경우에만 하단에 이전 기기 여행 복구를 제공하고 기존 데이터를 보존한다. 혼자 쓰는 여행도 계정에 저장하며 초대 전에는 본인만 접근한다. 메뉴 항목 선택, 바깥 누르기, Escape 키로 메뉴를 닫을 수 있다.
- 여행 카드에 목적지 대표 사진을 표시한다. 일본 오사카는 오사카성, 요나고는 요나고성 터를 사용한다. 다른 도시는 선택 위치와 문서 좌표가 일치하는 경우 라이선스를 확인한 대표 사진을 사용한다. 사진이 없으면 기본 일러스트를 표시한다.
- 홈에서 가장 가까운 여행을 큰 카드로 보여주며 사진 위에는 여행 이름·지역·기간을 표시한다. 다른 여행은 아래의 기존 카드 목록으로 표시한다. 새 여행 만들기는 다가오는 여행 제목 옆에 둔다.
- 상단 브랜드는 나비 아이콘과 '호랑나비'만 표시하며 영문 부제와 우측 '나의 여행' 버튼은 두지 않는다. 로고 클릭으로 홈으로 돌아가며 일정 화면의 뒤로 가기는 유지한다. 홈 상단 영문 슬로건과 '작은 설렘의 시작' 문구는 제거하고 소개 영역은 귀여운 호랑이 아이콘을 사용한다.
- 여행 생성은 실제 저장 기능이다. HTTPS/localhost뿐 아니라 휴대폰 LAN HTTP 주소에서도 여행·일정 ID를 생성할 수 있어야 한다. 새 여행 날짜는 오늘로 시작하고 사용자가 변경할 수 있다. 시작일을 종료일 뒤로 옮기면 종료일도 함께 맞춘다.
- 예정된 여행과 지난 여행 분리. 여행 이름, 지역, 시작·종료일 표시.
- 여행 이름은 선택 입력이다. 공백 또는 미입력 시 선택한 도시 이름에 ' 여행'을 붙여 저장한다(일본·도쿄 → 도쿄 여행). 직접 입력한 여행지는 마지막 '·' 구간을 사용하며, 이미 '여행'으로 끝나는 이름은 중복해서 붙이지 않는다. 직접 지은 이름은 그대로 유지한다. 저장 전에 자동 이름을 입력칸의 예시로 표시하며 최대 100자를 유지한다.
- 여행 생성·수정·삭제와 일정 화면 진입. 오사카 예시를 최초 실행 시 제공.
- 여행 생성/수정의 여행지 입력은 국가·지역 선택 → 도시·여행지역 선택 순서로 제공한다. 국가·지역 249개를 한국어로 표시하고 자주 찾는 국가를 위에 배치한다. 기본 목록은 50개 국가의 351개 도시·여행지역이며 유명 도시와 소도시를 함께 포함한다(일본 75곳).
- 도시 목록은 한글·영문·등록된 현지어로 로컬 필터링하며 입력 중 API 요청하지 않는다. 더 보기와 선택한 여행지 요약, 도시 변경을 제공한다. 국가를 변경하면 이전 도시 선택/검색 결과를 초기화한다.
- 목록에 없는 도시는 버튼으로 선택 국가 안의 도시/소도시를 추가 검색한다. 국가 코드와 city/locality 레이어를 서버에 전달하고 응답에서도 국가 및 도시 유형을 검증한다. 카페/시설 등 일반 장소는 도시 선택 결과에서 제외한다. 기존 검색과 2초 간격·캐시·타임아웃을 공유한다.
- 도시 직접 입력 및 여러 국가/기존 형식 여행지의 자유 입력을 유지한다. 도시가 선택되지 않았으면 여행을 저장하지 않는다. 저장 형식은 기존 region 문자열('일본 · 요나고')을 유지하여 기존 여행/JSON 백업을 변경하지 않는다. 추가 검색에 한국어 이름이 없는 경우 원문이 남을 수 있다.

### 여행 일정

- 좌표나 주소가 있는 일정 카드 상세에서 **현 위치에서 길찾기**를 제공한다. Google 지도 링크에 목적지만 전달하고, 출발지 선택과 위치 권한은 Google 지도에서 처리한다.
- 선택한 도시의 국가 코드·도시명·선택적 좌표를 여행의 destination에 저장한다. 기본 도시 버튼 선택 시 국가로 제한한 Photon 도시 검색으로 위치를 확인하고 이름이 일치하는 단일 결과만 연결한다. 추가 검색 결과를 직접 선택하면 그 결과 좌표를 사용한다. 동명 결과/검색 실패는 안내하며 좌표 없이 저장할 수 있다. 입력 중 요청은 하지 않는다.
- 좌표가 있는 일정은 기존처럼 핀 범위가 우선이며, 핀이 없는 날짜에는 여행 도시를 표시한다. 장소 추가 지도와 주변 검색 기준은 여행 도시, 없으면 당일 일정, 여행 전체 일정 순으로 결정한다. 일정 수정은 해당 장소 좌표를 우선한다. 좌표 없는 기존 여행도 그대로 읽고 편집하며 여행 수정에서 도시 위치를 연결할 수 있다. 기존 버전 1 백업은 유지하고 선택적 destination 필드를 추가 검증한다.
- 화면 순서: 여행 배너 → 인터랙티브 지도 → 날짜 탭 → 일정 카드 → 추가 버튼. PC는 지도와 일정의 나란한 배치를 허용한다.
- 선택 날짜의 일정만 지도에 번호 핀으로 표시한다. 좌표 없는 일정은 목록에 유지한다.
- 카드 선택: 지도 이동·확대, 카드 강조, 주소·메모·좌표 및 편집 기능 표시.
- 펼친 일정의 복사 버튼으로 날짜와 내용을 확인·수정한 뒤 같은 여행의 원하는 날짜 끝에 복사본을 추가한다. 장소·주소·좌표·사진·시간·카테고리·메모를 유지하고 새 ID를 발급하며 원본은 바꾸지 않는다. 예약에서 생성한 일정의 복사본은 예약 연동을 제외한 일반 일정으로 저장한다. 공유·기기 모드의 기존 저장 경로와 충돌 처리를 사용하며 취소·뒤로가기에는 저장하지 않는다.
- 핀 선택: 카드로 스크롤 및 강조. 순서 변경 시 번호 갱신.
- 같은 날짜의 일정은 카드 왼쪽 손잡이를 끌거나 위·아래 버튼을 눌러 순서를 바꿀 수 있다. 드래그 중에는 삽입 위치를 표시하며, 놓을 때 새 순서를 한 번 저장한다.
- 날짜 변경 및 전체 장소 보기 버튼으로 지도 범위를 조정한다.
- 선택 날짜의 좌표 있는 핀을 목록 순서대로 청록색 선으로 연결한다. 날짜·순서·추가·수정·삭제 시 갱신하고 좌표 없는 일정은 연결에서 제외한다. 실제 도로·도보 경로가 아닌 순서 연결선임을 안내한다. Google Maps와 무료 지도 모두 지원하며 경로 계산 API는 호출하지 않는다.
- 연결선은 약 1.5px의 가는 청록색 점선으로 표시하고 굵은 흰색 테두리는 사용하지 않는다.
- 일정을 스크롤하는 동안 지도는 화면에 고정한다. 모바일에서는 지도 높이를 화면에 맞춰 줄이고, 지도 아래에서 읽고 있는 카드에 따라 번호 핀 강조와 지도 위치를 변경한다. 스크롤만으로 상세 내용을 펼치지 않으며 직접 선택한 카드의 상세 정보는 유지한다. 핀 선택으로 스크롤할 때 카드가 고정 지도에 가려지지 않아야 한다. 지도 이동은 기존 인스턴스를 사용한다.
- 모바일 지도는 스크롤 중에도 같은 높이를 유지한다. 날짜 탭은 기기의 현재 날짜가 여행 기간 안에 있을 때 오늘을 표시하고, 사진 유무와 관계없이 일정 이름은 같은 위치에 정렬한다.

### 일정별 방문 후기

- 펼친 일정의 복사·수정·삭제 줄에 후기 버튼을 제공한다. 기존 교통편/계획 메모와 분리된 글(최대 3,000자)과 사진(일정당 최대 3장)을 여행 참여자가 함께 보고 수정한다. 본문 또는 사진만 저장할 수도 있다. 저장한 후기는 카드 상세에 표시하고 사진을 누르면 확대/축소하며 압축본을 내려받을 수 있다.
- JPG·PNG·WebP·AVIF와 브라우저가 읽을 수 있는 HEIC/HEIF를 받는다. 원본은 25MB까지이며 기기 canvas에서 최대 1280px JPEG로 다시 인코딩한다. 원본 파일명과 EXIF/GPS를 저장/전송하지 않는다. 지원하지 않거나 읽을 수 없는 파일에는 JPG/PNG 재선택을 안내한다. 무료 운영을 위한 압축본이며 원본은 별도 보관하도록 안내한다.
- 사진 문자열은 장당 200KiB, 여행당 100장/합계 8MiB까지 저장하고 현재 용량을 표시한다. 공유 사진은 기존 Firestore의 사진별 문서로 분리하고 일정에는 참조만 저장한다. 기존 인라인 사진은 다음 내용 저장 시 사진 문서와 함께 원자적으로 이전한다. 일정 메타데이터는 권한 여유 포함 900KiB 이하로 유지한다. 한도 초과 시 저장 전 안내하고 입력을 유지한다. 새 Storage·외부 API·공개 사진 URL은 추가하지 않는다. 사진은 미리보기/자료 요청 시 읽으며 메모리에서만 재사용하고, 읽기·쓰기·용량의 프로젝트 무료 할당량은 계속 적용된다.
- 선택적 Stop.review로 version 1 백업과 호환하고 기존 데이터는 그대로 읽는다. 일정 수정/연결 예약 갱신은 보존하며 일정 복사본에는 방문 후기를 복사하지 않는다. 일정 삭제 시 후기와 사진도 삭제된다. 비우기는 저장해야 반영되며 취소·뒤로가기는 저장하지 않는다.
- 기존 공유 여행 revision과 참여 권한을 사용한다. 사진 생성/삭제도 부모 일정 변경과 같은 트랜잭션에 넣고 참여자만 사진을 읽을 수 있다. 저장 실패/충돌에는 글·사진을 유지하고 자동으로 덮어쓰지 않는다. 최근 변경에는 후기·사진 필드만 남기며 저장 구조 이전만으로 가짜 후기 변경을 기록하지 않는다. 사진을 서비스 워커 캐시나 오프라인 사본에 저장하지 않는다. 사진 준비/편집/백업 중 PWA 업데이트를 보류한다. JSON 백업은 사진을 모두 인라인으로 복원한 뒤 만들며 최대 32MiB, 여행별 백업도 제공한다. 큰 가져오기는 한 번의 트랜잭션 한도에 맞게 여행별로 나누어 안내하고 일부만 저장하지 않는다.

### 추가·수정
- 입력 창 안에 지도를 유지한다. 검색 결과를 선택하면 위치 핀 및 지도 이동.
- 장소 선택 화면은 검색창 → 지도 → 선택 장소 및 검색 결과 → 작은 검색 범위 선택창 순서로 배치한다. 검색창은 장소 이름과 모바일 Google 지도 공유 링크를 함께 받으며, 붙여넣은 링크는 즉시 해석해 이름·위치를 채운다.
- 검색 범위는 여행지 주변 우선, 현재 지도 안, 전체 지역을 지원한다. 주변 우선은 기준 좌표의 위치 편향을 적용하고 지도 안 검색은 보이는 영역을 검증한다. 전체 지역 검색에는 위치 제한을 두지 않는다. 검색 반경 선택과 위도·경도 직접 입력은 제공하지 않는다.
- 결과가 없으면 범위 제한 없이 다시 검색 버튼 옆에 Google 지도에서 검색 링크를 표시한다. 전체 지역에서도 결과가 없으면 Google 지도 링크만 표시한다.
- Google 지도는 한 손가락 드래그로 이동할 수 있도록 greedy 제스처 처리를 적용한다.
- 검색 출처는 장소 입력창의 저장 버튼 아래에 표시한다. 지도 자체에 포함된 필수 로고·저작권 표시는 지도 안에서 유지한다. 일정·항공편·숙소 예약 시간은 24시간제 시·분 선택으로 입력하고 분 단위의 기존 시간을 보존한다.
- 최대 12개의 결과에 상세 주소(구·동·우편번호 포함), 장소 종류, 기준점으로부터의 직선 거리를 표시한다. 기본 관련도순과 가까운순 정렬을 제공한다. 결과 선택 시 지도와 폼에 반영하고 선택한 지점을 표시하되 저장은 별도로 한다. 반경/지도 범위가 다른 검색은 캐시도 분리한다.
- 검색 결과는 한국어 이름을 큰 주 제목으로, 원문 이름은 바로 아래 작은 보조 문구로 표시한다. 한국어명 속성을 우선 사용하며, 없으면 알려진 명소·브랜드·공항의 정확한 별칭을 적용한다. 주소도 알려진 국가·도시·구 이름을 한국어로 표시하고 원문 주소는 아래 작게 보존한다. 미등록 이름/주소 일부는 원문을 유지하며 한국어 이름이 없는 결과에 대한 안내를 제공한다. 검색 제공자나 과금 번역 API는 추가하지 않는다.
- 장소 선택에서 한국어 검색어는 원문으로 먼저 검색한다. 결과가 없으면 의미를 번역한 영어 검색어로 한 번 재검색하고 실제 사용한 영어를 결과 안내에 표시한다. 한국어 결과가 있거나 원문 검색이 서버 오류로 실패하면 영어 재검색을 실행하지 않는다.
- 등록된 도시·명소·숙소의 영문 표기를 우선 보존하고 일반 시설명은 뜻으로 번역한다. 나머지 표현은 MyMemory의 무료 익명 번역을 사용하며 번역 결과에 남은 한글 이름은 발음 기반 로마자로 보완한다. 번역은 8초 제한과 세션 캐시 100개를 적용하고 실패·한도 초과 시 원래 검색 결과와 Google 지도 검색을 유지한다.
- 원문과 영어 재검색은 같은 지도 범위·국가 제한·좌표 우선순위를 사용하고 Photon 요청 간격 2초를 지킨다. 검색창 입력 중 요청하지 않으며 검색창이 닫히면 대기·번역·재검색을 취소한다. 도시 선택 등 기존 호출자의 별칭 정규화는 유지한다.
- 한국어 철도역 검색에 음식점 등 다른 종류의 장소가 반환되면 제외해 영어 재검색을 막지 않도록 한다. 검색 데이터에 역 자체가 없을 때는 영어 검색에서도 인근 도로가 나올 수 있으므로 결과의 종류를 표시한다.
- '오사카 공항'은 오사카 국제공항(이타미) 이름으로 검색하며 간사이 공항과의 구분 선택지를 제공한다. 선택지만 누르면 검색어만 변경하고 요청하지 않는다. 결과가 없고 범위가 제한되어 있으면 명시적인 '범위 제한 없이 다시 검색' 버튼으로 재검색할 수 있다. 범위를 몰래 넓히거나 여러 요청을 자동 실행하지 않는다.
- '요나고 공항', '요나고 기타로 공항', YGJ, Yonago/Miho 공항의 통용명을 Yonago Airport 검색으로 보완하고 실제 결과에는 한국어 이름과 원문을 함께 표시한다. 공항 검색어이며 지역 제한 상태라면 검색 전에 '공항 이름으로 전체 지역 검색' 버튼을 제공한다. 다른 도시의 공항이 현재 일정 주변 범위에서 제외될 수 있음을 안내한다.
- 장소 이름, 주소, 위도, 경도, 날짜, 선택 시간, 카테고리, 메모 저장.
- 지도 클릭으로 직접 위치 선택. 좌표 및 시간 없이 저장 가능.
- 일정 수정·삭제·같은 날짜 내 위/아래 순서 변경. 수정 중 날짜 이동 가능.

### 저장 및 복구
- 버전 1 스키마로 localStorage에 저장. JSON 백업 다운로드와 검증 후 복원.
- 복원은 전체 교체임을 확인한다. 손상 데이터 자동 덮어쓰기 금지. 저장 실패 안내.

## PWA 설치

- 오른쪽 상단 메뉴에서 설치 창 또는 기기별 설치 안내를 연다. 안내 창은 뒤로가기로 닫고, 설치된 독립 화면에서는 설치 항목을 숨긴다. 나비 아이콘과 한국어 이름·노치 여백을 지원한다.
- GitHub Pages 하위 경로에서 실행하며 계정·여행별 권한 검사를 유지한다. 기존 offline-worker.js를 공유하고 정적 코드·스타일만 캐시한다. 인증·Firestore·지도·검색·사진 응답은 캐시하지 않는다.
- 인터넷 없는 첫 진입은 기존 읽기 전용 오프라인 사본으로 이동한다. 사본 미저장 시 안내를 표시하며 새 유료 API·오프라인 쓰기는 추가하지 않는다.
- 새 버전이 준비되면 현재 화면 위에 필수 업데이트 팝업을 자동 표시한다. 업데이트하기 버튼만 두고 닫기·취소·나중에 하기와 Escape/배경 누르기로 닫기를 제공하지 않는다. 입력창·준비물/닉네임 입력·저장·드래그·오프라인 사본 저장 중에는 해당 작업 종료 후 표시한다. 입력을 강제로 버리거나 다른 탭을 갑자기 새로고침하지 않는다.
- 앱 복귀·연결 복구·화면이 열린 동안 1분 간격으로 새 버전을 확인한다. 숨겨진 화면과 오프라인에서는 확인·적용을 보류한다. 다른 탭에서 적용해도 현재 탭은 편집을 마친 뒤 필수 팝업을 표시한다. 적용 실패·시간 초과에는 오류와 재시도를 제공한다. 자세한 사용법은 PWA_SETUP.md를 따른다.

## 블로그 글쓰기 자료

- 기본 문체는 내 말투 + 요즘 블로그 느낌이다. 선택한 후기의 어투/표현/평가를 보존하고 문단·도입·소제목을 자연스럽게 다듬는다. 유행어와 과장을 강요하거나 실제 유행을 알고 있다고 단정하지 않는다. 글이 부족하면 담백하고 친근한 문체로 처리하고 기존 두 문체도 선택할 수 있다.

- 여행 상세 상단의 블로그 글쓰기에서 여행 전체/하루, 친근한 후기/담백한 정보 중심 문체, 후기 사진 포함 여부를 선택한다. 기본은 후기 또는 사진이 있는 일정만 날짜 순서와 같은 날의 기존 일정 순서대로 정리한다. 후기 없는 일정도 포함할 수 있으며 계획 자료/방문 미확인으로 명시한다.
- 선택한 일정의 이름·분류·사용자 후기, 여행 이름·여행지·기간과 사진 파일명을 한국어 ChatGPT 작성 요청문으로 만든다. 제목 후보·도입·날짜/장소별 본문·마무리·해시태그, 사진 위치와 설명을 요청한다. 경험·맛·가격·운영시간 등을 지어내지 않고 첨부하지 않은 사진을 본 것처럼 쓰지 않도록 안내한다. 자료의 문구는 지시가 아니라 참고 데이터로 취급한다.
- 요청문 미리보기와 복사, 사진/장소 대응 미리보기, 요청문·사진 ZIP 다운로드를 제공한다. Clipboard 실패 시 요청문을 펼쳐 선택하고 수동 복사를 안내한다. ZIP에는 README.txt, chatgpt-request.txt, photo-guide.txt와 날짜/일정 순번별 JPEG를 담는다. 한글 UTF-8과 CRC32를 지원하고 사진은 기존 압축본을 사용한다. 사진이 없으면 글쓰기 요청문만 사용한다. 빈 자료는 복사/내려받기를 막고 범위 선택 또는 후기 추가를 안내한다.
- 사용자가 ChatGPT 새 대화에 요청문을 붙여넣고 ZIP을 푼 photos 폴더의 파일을 직접 첨부한다. 앱은 ChatGPT/API에 자료를 자동으로 전송하거나 글을 생성/게시하지 않는다. 새 창은 매개변수 없는 https://chatgpt.com/ 주소만 사용한다. AI API 키·새 결제·새 저장소·Firestore 추가 조회/쓰기는 없다. ChatGPT에서의 이용 조건/한도는 해당 계정에 따른다.
- 교통편 memo, 주소·좌표·지도 링크, 예약/예약 코드, 가계부, 참여자/계정, 내부 ID와 기록은 자료에서 제외한다. 사용자가 직접 작성한 후기·사진 자체의 개인정보와 동행인 기록은 전달 전 확인하도록 안내한다. 기존 여행 데이터/최근 변경/권한/백업은 그대로다. 자료 창은 최신 접근 가능한 여행에서 읽으며 취소·뒤로가기로 닫고 PWA 업데이트를 보류한다. 자료만 정리하므로 후기 저장이나 생성 상태를 추가하지 않는다.

## 기념품 리스트

- 여행 상세의 기념품 탭에서 여행별 이름(필수), 받을 사람(선택), 수량(1~999개), 메모(선택)를 추가·수정·삭제하고 구매 여부를 체크한다. 구매 완료 항목 수와 진행률을 표시한다. 여행당 최대 200개이며 이름 150자, 받을 사람 100자, 메모 1000자로 제한한다.
- 공유 여행 참여자 모두가 같은 구매 여부를 보고 편집한다. 준비물처럼 개인마다 체크하는 방식은 아니다. 기존 Firebase 여행 문서·revision 검사로 저장하며 실패/충돌 시 편집창과 입력을 유지하고 최신 상태에서 다시 편집하도록 안내한다. 가계부에 지출을 자동 생성하지 않는다.
- Trip.souvenirs 선택 필드를 사용하고 구형 여행·version 1 JSON 백업을 유지한다. 기기 여행도 지원하며 여행 수정 시 목록을 보존한다. 기념품 추가·수정·삭제·구매 완료/해제는 최근 변경 내역에 표시한다. 뒤로가기·닫기·Escape로 편집창을 닫고 새로고침 후 선택 탭을 복원한다. 지도는 탭 전환으로 새로 생성하지 않는다.
- 기존 참여자 권한을 따르며 새 API·컬렉션·규칙 설정은 필요 없다. 오프라인 읽기 사본에는 기념품을 넣지 않으며 온라인 공유 목록과 JSON 백업을 이용한다.

## 가계부 원화 환산 누적 합계

- 가계부 상단에 여행 전체의 공동·개인·단순 기록용 지출을 합산한 원화 환산 누적 지출을 표시한다. KRW는 그대로 더하고 JPY·USD 및 기존 지원 통화는 공용 하루 환율을 사용한다. 소수 통화의 최소 단위를 반영하고 전체 합산 후 원 단위로 반올림한다. 기존 지출과 통화별 정산은 변경하지 않는다.
- 한국 시간 매일 오전 8시(UTC 23시)에 기존 Pages 워크플로를 예약 실행해 Coinbase 공개 API의 공용 환율을 준비한다. 앱을 닫아두어도 실행된다. 일반 코드 배포는 이미 공개된 당일 파일이 있으면 재사용한다. 최초 적용/파일 소실 후에는 한 번 초기화한다. 외부 API 실패는 이전 파일의 실제 조회 시각을 보존하며 최초 실패 시 사용 불가를 명시한다.
- 앱은 같은 사이트의 exchange-rates.json만 읽으며 외부 환율 API를 호출하지 않는다. 공개 환율만 전용 localStorage에 저장해 앱 재시작/새로고침에도 재사용한다. 여행 데이터·기기 여행 복구 판정과 분리한다. 한국 시간 오전 8시를 경계로 하루 환율을 유지하고, 가계부를 계속 열어두면 다음 경계에 한 번 확인한다. 숨김/오프라인은 요청하지 않고 복귀 때 확인한다. 1분 폴링을 제거하며 파일 갱신 대기/조회 실패 때만 5분 간격으로 공용 파일을 재확인한다.
- 조회 결과가 이미 당일 값이면 수동 새로고침을 표시하지 않는다. 실패·이전 값은 다시 확인과 이전 조회 환율 적용을 표시한다. 파일/저장소 형식·유한 양수 환율·한국 날짜 경계·미래 시각을 검증하고 8초 제한/요청 중복 방지/저장소 오류 대처를 유지한다. 기기가 해외 시간대로 바뀌어도 오전 8시 기준과 표기 시각은 Asia/Seoul이다.
- 환율 출처, 실제 갱신 시각과 엔화 100엔 기준 환율/통화별 환산액을 표시한다. 예약 실행과 배포 지연으로 정각 반영을 보장하지 않는다. 당일 파일이 준비될 때까지 이전 환율임을 안내하며 실제 환전·카드 청구액/수수료와 차이가 있는 참고 합계다. 누락 통화/안전한 숫자 범위 초과는 불완전한 전체 합계를 표시하지 않는다. 원화만 있으면 외부 조회 없이 합산한다.
- 새 유료 API·인증키·Firestore 쓰기/권한 변경은 없다. 환율 JSON에는 공개 환율과 조회 시각만 포함하고 사용자 지출/여행/인증 정보를 보내거나 공개하지 않는다. JSON은 서비스 워커 정적 코드 캐시와 PWA 버전 해시에서 제외해 하루 환율 갱신만으로 필수 앱 업데이트를 만들지 않는다. 공식 환율 API: https://docs.cdp.coinbase.com/coinbase-app/track-apis/exchange-rates . 예약 제약: https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule .

## 공동 가계부와 오프라인 사본

- 공유 여행의 가계부 탭에서 여행 참여자가 지출 이름, 결제 날짜, 금액·통화, 결제자와 공동·개인·단순 기록용 구분을 추가·수정·삭제한다. 공동 지출은 현재 참여자끼리 균등하게 나누어 통화별로 상계하며 개인 지출은 전체 합계에만 포함한다. 나눠지지 않는 최소 통화 단위는 더 많이 결제한 참여자부터 부담한다. 참여자 변경 시 과거 지출의 정산도 다시 계산하며, 이전 참여자의 공동 결제가 남으면 정산 확인 안내를 표시한다. 단순 기록용은 결제자 선택 없이 총지출에만 포함하고 균등 정산에서 제외한다. 개인 지출과 단순 기록용도 여행 참여자 모두에게 표시한다. 기존 지출의 구분은 자동으로 바꾸지 않으며 수정 시 세 구분 사이를 전환할 수 있다. 원화(KRW)는 정수 원 단위로 입력하고 12,000원처럼 표시한다. 통화별 정산은 원래 통화로 유지하며 원화 환산 누적 합계를 별도로 표시한다.
- 여행 화면 오른쪽 상단 메뉴에서 일정과 예약 시간·장소를 이 기기에 저장한다. 저장한 일정은 같은 메뉴에서 열 수 있다. 오프라인 사본은 한 여행씩 읽기 전용으로 열고 직접 갱신하거나 삭제할 수 있다. 지도, 사진, 예약번호, 가계부는 사본에 저장하지 않는다. 공유 계정에서 로그아웃하면 해당 기기의 공유 사본을 지운다.

## 여행별 예약 정보

- 숙소 예약은 여행 기간 안의 현지 체크인·체크아웃 날짜와 시간으로 일정을 생성한다. 연박 중에는 체크인 다음 날부터 체크아웃 전날까지 숙소 출발을 각 날짜의 첫 순서에 두고, 체크아웃 날은 체크아웃 일정을 첫 순서에 둔다. 당일 체크인·체크아웃은 시간순으로 배치한다. 예약 수정·삭제 시 연결된 일정도 갱신한다.

- 여행 상세 상단에 예약 탭을 두고 항공편명과 현지 출발 시간, 숙소 이름·주소·현지 체크인과 체크아웃을 등록한다. 항공편명의 영문은 입력 즉시 대문자로 바꾼다. 예약번호와 예약 확인 링크 입력 및 표시는 제거하며 기존 저장 데이터는 읽을 수 있다.
- 숙소 예약에서 일정 추가와 같은 검색·지도·공유 링크 선택 화면을 사용한다. 선택한 숙소의 이름·주소·좌표·지도 링크를 저장하고 연결된 모든 숙소 일정에 좌표와 링크를 전달한다. 체크인·체크아웃 날짜·시간은 각각 날짜와 시간 입력으로 나눠 표시하며 둘 다 입력한다.
- Android 공유 링크가 장소 ID만 포함하면 해당 ID의 공개 임베드 지도에서 같은 장소 레코드의 이름·주소·핀 좌표를 읽는다. 임베드 지도 내부 리디렉션도 검증하며 지도 화면 중심은 장소 핀으로 사용하지 않는다. 좌표 확인에 실패해도 이미 확인한 장소 이름은 반환한다.
- 예약을 추가·수정·삭제할 수 있으며, 기기 저장과 공유 여행 및 JSON 백업에 포함한다. 기존 백업의 빈 예약 목록도 지원한다. 예약을 열 때 여행 지도는 가려지고 기존 지도 인스턴스를 유지한다.
- 인천공항 출발 정기 여객편은 편명과 날짜로 조회해 현지 예정 출발 시간과 출발·도착 공항을 채운다. 운항 기간과 요일을 확인하며 사용자가 결과를 확인한 뒤 저장한다. 조회가 불가한 편은 직접 입력할 수 있다.
- 출국편 예약은 현지 도착 날짜·시간의 도착 공항을, 복귀편 예약은 현지 출발 날짜·시간의 출발 공항을 일정에 연결한다. 여행 기간 안의 이벤트를 예약당 하나만 생성하고 예약 수정·삭제에 맞춰 갱신한다. 등록된 공항 좌표는 지도 핀에 사용한다.

## 장소 보관함
- 여행 배너 아래 '여행 일정'과 '장소 보관함' 보기 전환을 제공한다. 보관함은 여행별로 분리되며 후보 수를 표시한다. 두 보기에서 지도 인스턴스를 재사용한다.
- 날짜 미정 후보를 장소 검색/지도 클릭/직접 입력으로 추가하고 이름·주소·좌표·카테고리·메모를 저장한다. 날짜와 시간은 후보에 저장하지 않으며 좌표 없이도 저장할 수 있다. 기존 일정 편집기의 지도/검색 조건·제한·오류 처리·한국어 표기를 공유한다.
- 후보 목록 번호와 지도 핀 번호를 연결하고, 카드/핀 선택 시 지도 이동·카드 스크롤·상세 강조를 제공한다. 후보 번호는 방문 순서가 아니므로 연결선을 표시하지 않는다. 전체 장소 보기와 후보 수정·삭제를 제공한다.
- 후보 상세에서 여행 기간 안의 날짜를 선택해 '일정으로 이동'한다. 선택 날짜의 마지막 일정에 시간 미정으로 추가하고 후보는 보관함에서 제거한다. 같은 ID와 모든 장소 정보를 유지하고, 중복 이동/잘못된 날짜 이동은 막는다. 이동 후 해당 날짜의 일정 보기를 연다.
- Trip.savedPlaces는 선택적 배열로 추가한다. 기존 version 1 데이터와 백업에서 누락된 배열은 화면에서 빈 보관함으로 취급한다. 새 데이터는 localStorage와 JSON 백업에 포함하며 복원 시 필드/좌표/중복 ID를 검증한다. 여행 수정 시 후보를 보존한다.

## 여행별 준비물

- 공유 여행은 항목마다 내 완료 체크 하나와 해당 여행의 참여자별 완료 수를 표시하고 전원이 체크하면 모두 완료다. 같은 항목을 참여자들이 동시에 체크해도 최신 서버 상태에 각자의 변경을 적용한다. 기존 공유 체크는 어느 계정이 완료했는지 알 수 없으므로 재확인을 안내한다. 기기 여행은 기존 완료 체크를 사용한다.
- 여행 배너 아래 '준비물' 탭을 제공하고 완료/전체 개수를 표시한다. 준비물 화면에서는 지도를 숨기며 일정/보관함으로 돌아올 때 기존 지도 인스턴스를 재사용한다.
- 준비물 이름 추가, 이름 수정/취소, 삭제 확인, 완료 체크/해제를 지원한다. 체크 여부와 항목 순서를 유지하며 완료한 항목은 취소선으로 구분한다. 공백뿐인 이름은 저장하지 않고 입력 이름은 최대 150자다.
- 완료 개수와 진행률을 표시하고 빈 목록 안내를 제공한다. 모바일에서 체크 영역과 수정·삭제 버튼을 터치하기 쉽게 배치한다. 광고/추천 항목이나 외부 API는 사용하지 않는다.
- Trip.packingItems는 선택적 배열이며 각 항목은 id/name/completed를 저장한다. 구형 데이터에 필드가 없으면 빈 목록으로 처리하고 기존 version 1 백업과 호환한다. 복원 시 형식·중복 ID·완료 값 타입을 검증한다. localStorage/JSON 백업 및 여행 편집 시 준비물을 보존한다. 여행 간 목록과 완료 상태는 분리된다.

## 지도 및 검색 제약

- 일정 카드에는 순번 아래에 시간을 표시한다. 일정의 좌표 주변 위키백과 문서에서 이름이 일치하고 위키미디어 공용에서 재사용 조건을 확인한 사진만 왼쪽에 자동 표시한다. 사진에 저작자와 라이선스를 표시하고 일치 항목이 없으면 생략한다. 기존에 저장한 사진 URL은 호환을 위해 유지한다. 브라우저 뒤로가기는 편집창을 먼저 닫고 여행 상세에서는 여행 목록으로 돌아간다.

- 일정·보관함·숙소 예약은 검색창에 붙여넣은 Google 지도 공유 링크를 장소 선택으로 처리한다. 새 링크를 선택하면 기존 선택을 대체하고, 변환 요청 이후 직접 수정한 이름과 위치는 응답으로 덮어쓰지 않는다. 변환 서버는 Google 지도 도메인 안의 리디렉션을 최대 6번 따라가며, URL의 명시된 장소 좌표와 공개 페이지의 장소 메타데이터를 확인한다. 지도 카메라 중심을 장소 좌표로 사용하지 않는다. 모바일 공유 텍스트의 링크 앞뒤 설명과 쿼리 매개변수를 지원하며 링크와 좌표는 공유 저장 및 JSON 백업에 포함된다.

- 일정과 보관함에서 전체 지역 검색은 여행지 주변 결과를 우선하되 반경으로 제외하지 않는다. 장소 이름과 주소를 함께 검색한 후 주소만 따로 검색할 수 있다. 주소 결과는 장소 이름을 유지하며 지도에서 위치를 확인한다.
- 검색 서비스에 장소가 없을 때 Google 지도에서 찾은 공유 링크를 검색창에 붙여넣거나 호랑나비 지도에서 직접 장소를 선택한다.
- 사용자가 Google Maps 전환을 선택했다. `VITE_GOOGLE_MAPS_API_KEY` 설정 시 Maps JavaScript API를 한국어(`language=ko`, `region=KR`)로 로드한다. Advanced Markers로 번호 핀을 표시하며 배포 시 자체 Map ID를 사용한다. 키가 없으면 기존 MapLibre GL JS + OpenFreeMap으로 실행한다.
- Google 지도에서는 Google 로고/저작권을 유지하고 한국어 표시를 요청한다. 실제 번역 범위는 Google 데이터에 의존한다. 무료 지도에서는 OpenStreetMap 출처를 유지하며 한국어 → 영어 → 기존 이름 순으로 표시한다. 도로 번호·건물 번호 등 지명 외 라벨은 그대로 유지한다.
- Photon 공용 데모 API를 이용한다. 버튼 제출만 요청, 최소 2초 간격, 동시 요청 방지, 세션 캐시(최대 100개), 12초 타임아웃. 결과 없음/네트워크/서버 오류 안내.
- 공용 서버의 안정성은 보장되지 않는다. 한국어 검색 결과가 적으면 현지어/영문과 도시를 함께 입력한다. 검색은 전 세계 검색이다.
- 좌표 없는 입력 및 편집은 외부 지도·검색 서버 상태와 독립적으로 동작한다.
- 추천 화면에만 사용자가 승인한 Google Places API (New)를 서버 제한과 함께 사용한다. 일정 추가 장소 검색은 Photon을 유지하며 Routes/Street View는 호출하지 않는다. 과금은 지도 로드 기준이고 무료량 안에서 운영하는 것을 목표로 하며, 항상 무료라고 보장하지 않는다. 설정과 비용 안내는 `docs/GOOGLE_MAPS_SETUP.md`를 따른다. 유료 경로 계산, 이동 시간 추정, 자동 최적 경로는 포함하지 않는다.

## 후속 개발
1. 장소 보관함 확장: 일정에서 보관함으로 되돌리기, 후보 정렬/필터 등은 후속 범위.
2. 준비물 확장: 분류/담당자/공통 템플릿은 후속 범위이며 현재 목록은 사용자가 직접 구성한다.
3. Firebase Authentication/Firestore: 여행별 초대·승인과 역할 규칙, 실시간 공동 편집 및 충돌 정책을 구현했다. 무료 할당량을 유지한다.
4. PWA 설치·캐시 갱신 정책·오프라인 사용 안내를 구현했다. 실제 휴대폰 설치와 설치 후 Google 로그인을 확인한다.

## 배포 및 개인정보
GitHub Pages에 공개 배포했다: https://ksy980324.github.io/horangnabi-v2/ . 정적 파일 공개와 여행 데이터 접근은 별개다. 공유 여행은 Firebase의 해당 여행 참여자만 접근하고 기기 여행은 localStorage에 저장한다. 앱 소스와 UI는 공개된다. 실제 여행 데이터를 소스에 커밋하지 않는다. 외부 서버에는 지도 타일 요청 및 사용자가 제출한 장소 검색어가 전달된다.

- v2 폴더 내용을 별도 저장소의 최상위에 둔다. 상위 기존 앱은 변경/업로드하지 않는다. GitHub Actions에서 main push 또는 수동 실행으로 설치→타입 검사→테스트→빌드→dist 업로드→Pages 배포를 수행한다.
- configure-pages의 base_path에 맞춰 PAGES_BASE_PATH를 빌드 환경에 지정한다. 로컬 기본 base는 상대 경로를 유지한다. 앱은 클라이언트 내 상태로 화면을 전환하므로 별도 서버 경로 재작성은 필요하지 않다.
- GitHub Actions Secret GOOGLE_MAPS_API_KEY와 Variable GOOGLE_MAP_ID를 빌드 시 VITE 환경 변수로 전달한다. 배포 시 누락/예시 키/DEMO_MAP_ID는 안내 후 중단한다. 값 자체를 로그에 출력하지 않으며 브라우저 키의 유효성/도메인 허용은 별도 확인한다. 로컬 키 없는 무료 지도 실행은 유지한다.
- .env.local을 포함한 환경 파일, node_modules, dist, 앱 JSON 백업은 커밋에서 제외한다. 키는 빌드된 브라우저 코드에서 보일 수 있으므로 실제 호스트에 대한 웹사이트 제한과 Maps JavaScript API 제한을 유지한다. 경로가 생략되는 referrer를 고려해 GitHub Pages 호스트를 허용한다.
- 새 배포 주소에는 기존 localStorage 데이터가 자동 이전되지 않는다. 기기 여행은 JSON 백업/복원으로 옮기며, 공유 여행은 로그인 후 Firebase에서 동기화한다. 실행 절차와 공개 범위는 docs/GITHUB_PAGES_SETUP.md에 기록한다.

## 여행별 참여자와 초대

- 계정 닉네임은 profiles/{uid}에 비공개로 저장하며 다른 사람의 프로필 조회·목록 열람은 금지한다. 참여자에게는 해당 여행의 memberNames에 복사한 닉네임만 제공한다. 여행 생성·새 참여 요청은 저장된 닉네임을 사용한다. 변경 시 참여 중인 여행의 본인 이름만 부분 갱신하며 일정·예약·권한을 덮어쓰지 않는다. 갱신 실패는 안내하고 다시 저장하거나 재접속하여 복구한다.
- 닉네임은 중복될 수 있으며 권한은 변하지 않는 UID로 판정한다. 기존 참여자가 아직 닉네임을 설정하지 않았다면 기존 여행에 저장된 표시 이름을 유지하고 본인이 로그인해 설정한 뒤 갱신한다. 참여 요청에는 요청 당시 이름을 표시하고, 승인 뒤 이름이 다르면 해당 계정의 접속에서 최신 닉네임으로 보완한다.
- Google 로그인 후 누구나 자기 여행을 생성한다. 목록은 sharedTrips에서 memberIds array-contains 현재 UID로 구독하며 여행당 최대 20명이다.
- 생성자는 여행장이다. 여행 공유에서 7일 유효 초대 링크를 만들거나 취소한다. 링크 수신자는 로그인 후 참여를 요청하고 여행장이 승인해야 일정을 볼 수 있다. 링크 미리보기는 여행 이름만 제공하며 참여자·일정은 노출하지 않는다.
- 여행장은 요청 승인·거절, 다른 참여자 제외, 여행 삭제를 관리한다. 일반 참여자는 일정·예약·준비물·가계부를 공동 편집하고 본인의 탈퇴만 할 수 있다. 여행장 변경은 후속이다.
- 모든 접근은 Firestore 규칙으로 검사하며 UI 숨김을 보안으로 간주하지 않는다. 권한 변경도 revision을 증가시키고 원자적으로 처리한다. 초대 토큰은 추측하기 어려운 난수와 만료를 사용하고 전체 목록 조회를 금지한다.
- 기존 settings/members의 두 계정과 trips 원본은 전환용으로 보존한다. 최초 접속 계정이 여행장인 새 공유 여행을 원래 참여자와 함께 생성하고 원본에 migratedTo를 기록하는 일을 한 트랜잭션으로 처리한다. 재접속·새 여행 삭제 후에도 중복 또는 부활시키지 않는다.
- 규칙 게시와 Pages 배포는 별개다. 새 코드를 배포하기 전에 firestore.rules를 게시하고 기존 창을 새로고침한다. 구체적인 적용 절차와 제약은 docs/FIREBASE_SETUP.md를 따른다.
- 에뮬레이터에서 두 그룹 격리, 미인증 접근, 역할 위조, 초대·만료, 승인·거절·탈퇴·전환을 검증한다. 실제 Google 로그인과 공개 서비스의 적용 검증은 별도로 보고한다.

## 추천 장소
- 추천 창 맨 위에 현재 페이지 장소 핀을 표시하는 Google 지도를 두고 카드/핀 선택을 연결한다. Google 키가 없는 환경에서는 Google 결과를 다른 제공자의 지도에 표시하지 않는다. 조회 후 추가한 카드는 완료 상태로 유지하며 페이지 번호가 밀리지 않게 한다.
- 새로고침에서 Firebase 로그인 복원 대기 화면을 별도로 표시하고, 인증 및 서버 여행 권한 확인 뒤 이전 여행·날짜·탭을 복원한다. 화면 위치는 계정별 sessionStorage에 ID/날짜/탭만 저장하며 접근 권한이 없거나 삭제된 여행은 복원하지 않는다. 브라우저 저장소가 차단되거나 명시적으로 로그아웃하면 로그인 유지가 제한될 수 있다.
- 추천 기준 날짜 선택을 없애고 조회 당시 기기의 현지 날짜에 있는 일정의 마지막 위치, 여행 도시, 여행 내 다른 일정 순으로 조회 기준을 정한다. 추가할 일정 날짜는 기존에 보고 있던 여행 날짜를 유지하고 추가 버튼에 월·일을 표시한다.
- 외국어 장소 이름은 무료 MyMemory로 한국어 번역을 시도하고 원문을 작게 병기한다. 결과·사진을 먼저 표시하고 번역을 뒤이어 반영한다. 번역 실패·한도 소진은 원문으로 대체하며 Google API 추가 호출이나 유료 번역은 하지 않는다. 번역 요청은 공개 장소명·언어만 포함하고 새 검색·창 닫기 때 취소한다.
- 사용자가 버튼을 누르면 전 세계 관광지·식당·카페를 기준점 주변 5km에서 Google 인기도순으로 최대 20곳을 한 번 조회하고 6곳씩 페이지를 나눠 표시한다. 페이지 이동은 추가 검색을 호출하지 않는다. 사진·평점·리뷰 수와 필수 출처를 표시한다. 추천 카드에서는 긴 주소를 숨기며 지도 핀은 유지한다. 장소별 소개는 현재 요청 필드에 없으므로 임의 생성하지 않는다. 사진은 화면 가까이 온 카드만 조회한다.
- 기존 일정·보관함 중복을 제외하고 보관함 또는 선택 날짜의 시간 미정 일정으로 추가한다. 공유 여행의 기존 저장·revision 검사·오류 안내를 사용한다.
- Firebase 토큰을 검증하는 기존 Worker의 /recommendations와 /recommendation-photo를 사용한다. 서버 전용 키는 Worker secret에만 등록한다. 원자적 영구 카운터로 검색·사진 각각 전체 사용자 합계 UTC 하루 25회·월 800회까지 예약하고, 설정/인증/카운터 실패 시 외부 호출을 차단한다.
- 사진·평점·API 응답을 영구 저장하거나 오프라인 캐시하지 않는다. Google 무료 한도와 결제 계정의 다른 사용은 별도 확인한다. Places 활성화·secret·Worker 배포가 필요하며 docs/RECOMMENDATIONS.md를 따른다.
