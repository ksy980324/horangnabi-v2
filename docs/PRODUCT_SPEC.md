# 호랑나비 제품 요구사항

## 목적과 디자인
사용자 두 명의 개인 여행 일정 관리 웹앱. Wanderlog의 계획 기능과 트리플의 지도·일정 사용 경험을 참고하되 독립적인 디자인과 코드를 사용한다. 무료 장기 운영, 모바일 편의성, 지도와 일정의 연동이 우선이다. 미니멀 80%와 여행 감성 20%: 흰색·연회색, 네이비 텍스트, 청록 포인트, 둥근 카드, 넉넉한 여백. 한국어 UI, 영문 파일명·식별자, UTF-8. 광고와 상품 추천을 넣지 않는다.

## 첫 번째 MVP
### 홈

- Firebase 설정이 있으면 공유 여행을 첫 화면으로 연다. 로그인 상태가 유지된 브라우저는 등록 계정의 여행 목록을 바로 보고, 처음 방문한 브라우저는 Google 로그인 버튼을 사용한다. 기기에 저장한 여행은 별도 메뉴로 연다.
- 헤더의 호랑나비 맞은편 메뉴에서 기기 여행 전환과 로그아웃을 연다. 메뉴 항목 선택, 바깥 누르기, Escape 키로 메뉴를 닫을 수 있다.
- 여행 카드에 목적지 대표 사진을 표시한다. 일본 오사카는 오사카성, 요나고는 요나고성 터를 사용한다. 다른 도시는 선택 위치와 문서 좌표가 일치하는 경우 라이선스를 확인한 대표 사진을 사용한다. 사진이 없으면 기본 일러스트를 표시한다.
- 홈에서 가장 가까운 여행을 큰 카드로 보여주며 사진 위에는 여행 이름·지역·기간을 표시한다. 다른 여행은 아래의 기존 카드 목록으로 표시한다. 새 여행 만들기는 다가오는 여행 제목 옆에 둔다.
- 상단 브랜드는 나비 아이콘과 '호랑나비'만 표시하며 영문 부제와 우측 '나의 여행' 버튼은 두지 않는다. 로고 클릭으로 홈으로 돌아가며 일정 화면의 뒤로 가기는 유지한다. 홈 상단 영문 슬로건과 '작은 설렘의 시작' 문구는 제거하고 소개 영역은 귀여운 호랑이 아이콘을 사용한다.
- 여행 생성은 실제 저장 기능이다. HTTPS/localhost뿐 아니라 휴대폰 LAN HTTP 주소에서도 여행·일정 ID를 생성할 수 있어야 한다. 새 여행 날짜는 오늘로 시작하고 사용자가 변경할 수 있다. 시작일을 종료일 뒤로 옮기면 종료일도 함께 맞춘다.
- 예정된 여행과 지난 여행 분리. 여행 이름, 지역, 시작·종료일 표시.
- 여행 생성·수정·삭제와 일정 화면 진입. 오사카 예시를 최초 실행 시 제공.
- 여행 생성/수정의 여행지 입력은 국가·지역 선택 → 도시·여행지역 선택 순서로 제공한다. 국가·지역 249개를 한국어로 표시하고 자주 찾는 국가를 위에 배치한다. 기본 목록은 50개 국가의 351개 도시·여행지역이며 유명 도시와 소도시를 함께 포함한다(일본 75곳).
- 도시 목록은 한글·영문·등록된 현지어로 로컬 필터링하며 입력 중 API 요청하지 않는다. 더 보기와 선택한 여행지 요약, 도시 변경을 제공한다. 국가를 변경하면 이전 도시 선택/검색 결과를 초기화한다.
- 목록에 없는 도시는 버튼으로 선택 국가 안의 도시/소도시를 추가 검색한다. 국가 코드와 city/locality 레이어를 서버에 전달하고 응답에서도 국가 및 도시 유형을 검증한다. 카페/시설 등 일반 장소는 도시 선택 결과에서 제외한다. 기존 검색과 2초 간격·캐시·타임아웃을 공유한다.
- 도시 직접 입력 및 여러 국가/기존 형식 여행지의 자유 입력을 유지한다. 도시가 선택되지 않았으면 여행을 저장하지 않는다. 저장 형식은 기존 region 문자열('일본 · 요나고')을 유지하여 기존 여행/JSON 백업을 변경하지 않는다. 추가 검색에 한국어 이름이 없는 경우 원문이 남을 수 있다.

### 여행 일정

- 좌표나 주소가 있는 일정 카드 상세에서 **현 위치에서 길찾기**를 제공한다. Google 지도 링크에 목적지만 전달하고, 출발지 선택과 위치 권한은 Google 지도에서 처리한다.
- 선택한 도시의 국가 코드·도시명·선택적 좌표를 여행의 destination에 저장한다. 기본 도시 버튼 선택 시 국가로 제한한 Photon 도시 검색으로 위치를 확인하고 이름이 일치하는 단일 결과만 연결한다. 추가 검색 결과를 직접 선택하면 그 결과 좌표를 사용한다. 동명 결과/검색 실패는 안내하며 좌표 없이 저장할 수 있다. 입력 중 요청은 하지 않는다.
- 좌표가 있는 일정은 기존처럼 핀 범위가 우선이며, 핀이 없는 날짜에는 여행 도시를 표시한다. 장소 추가 지도와 주변 검색 기준은 여행 도시, 없으면 당일 일정, 여행 전체 일정 순으로 결정한다. 일정 수정은 해당 장소 좌표를 우선한다. 좌표 없는 기존 여행도 그대로 읽고 편집하며 여행 수정에서 도시 위치를 연결할 수 있다. 기존 버전 1 백업은 유지하고 선택적 destination 필드를 추가 검증한다.
- 화면 순서: 여행 배너 → 인터랙티브 지도 → 날짜 탭 → 일정 카드 → 추가 버튼. PC는 지도와 일정의 나란한 배치를 허용한다.
- 선택 날짜의 일정만 지도에 번호 핀으로 표시한다. 좌표 없는 일정은 목록에 유지한다.
- 카드 선택: 지도 이동·확대, 카드 강조, 주소·메모·좌표 및 편집 기능 표시.
- 핀 선택: 카드로 스크롤 및 강조. 순서 변경 시 번호 갱신.
- 날짜 변경 및 전체 장소 보기 버튼으로 지도 범위를 조정한다.
- 선택 날짜의 좌표 있는 핀을 목록 순서대로 청록색 선으로 연결한다. 날짜·순서·추가·수정·삭제 시 갱신하고 좌표 없는 일정은 연결에서 제외한다. 실제 도로·도보 경로가 아닌 순서 연결선임을 안내한다. Google Maps와 무료 지도 모두 지원하며 경로 계산 API는 호출하지 않는다.
- 연결선은 약 1.5px의 가는 청록색 점선으로 표시하고 굵은 흰색 테두리는 사용하지 않는다.
- 일정을 스크롤하는 동안 지도는 화면에 고정한다. 모바일에서는 지도 높이를 화면에 맞춰 줄이고, 지도 아래에서 읽고 있는 카드에 따라 번호 핀 강조와 지도 위치를 변경한다. 스크롤만으로 상세 내용을 펼치지 않으며 직접 선택한 카드의 상세 정보는 유지한다. 핀 선택으로 스크롤할 때 카드가 고정 지도에 가려지지 않아야 한다. 지도 이동은 기존 인스턴스를 사용한다.
- 모바일 지도는 스크롤 중에도 같은 높이를 유지한다. 날짜 탭은 기기의 현재 날짜가 여행 기간 안에 있을 때 오늘을 표시하고, 사진 유무와 관계없이 일정 이름은 같은 위치에 정렬한다.

### 추가·수정
- 입력 창 안에 지도를 유지한다. 검색 결과를 선택하면 위치 핀 및 지도 이동.
- 검색 범위는 기존 일정의 위치 주변(5/20/50km), 현재 지도 안, 전체 지역을 지원한다. 기존 좌표가 있으면 여행 일정 주변을 기본값으로 하고 없으면 전체 지역으로 시작한다. 도시·상세 주소를 검색어에 추가할 수 있다. 서버 요청에 위치 편향과 영역 조건을 적용하며 응답도 좌표·반경·영역 기준으로 검증한다.
- 최대 12개의 결과에 상세 주소(구·동·우편번호 포함), 장소 종류, 기준점으로부터의 직선 거리를 표시한다. 기본 관련도순과 가까운순 정렬을 제공한다. 결과 선택 시 지도와 폼에 반영하고 선택한 지점을 표시하되 저장은 별도로 한다. 반경/지도 범위가 다른 검색은 캐시도 분리한다.
- 검색 결과는 한국어 이름을 큰 주 제목으로, 원문 이름은 바로 아래 작은 보조 문구로 표시한다. 한국어명 속성을 우선 사용하며, 없으면 알려진 명소·브랜드·공항의 정확한 별칭을 적용한다. 주소도 알려진 국가·도시·구 이름을 한국어로 표시하고 원문 주소는 아래 작게 보존한다. 미등록 이름/주소 일부는 원문을 유지하며 한국어 이름이 없는 결과에 대한 안내를 제공한다. 검색 제공자나 과금 번역 API는 추가하지 않는다.
- 무료 검색의 한국어 데이터 한계를 보완하기 위해 주요 공항의 한국어명·공항 코드와 일부 도시·명소 검색어를 영문명으로 정규화한다. 사용자가 검색 전에 보완된 이름을 확인할 수 있어야 한다. 공항 검색에는 공항 종류 필터를 적용하고 알려진 공항은 한국어명과 원문명을 함께 보여 준다. 좌표와 실제 검색 결과를 하드코딩하지 않는다.
- '오사카 공항'은 오사카 국제공항(이타미) 이름으로 검색하며 간사이 공항과의 구분 선택지를 제공한다. 선택지만 누르면 검색어만 변경하고 요청하지 않는다. 결과가 없고 범위가 제한되어 있으면 명시적인 '범위 제한 없이 다시 검색' 버튼으로 재검색할 수 있다. 범위를 몰래 넓히거나 여러 요청을 자동 실행하지 않는다.
- '요나고 공항', '요나고 기타로 공항', YGJ, Yonago/Miho 공항의 통용명을 Yonago Airport 검색으로 보완하고 실제 결과에는 한국어 이름과 원문을 함께 표시한다. 공항 검색어이며 지역 제한 상태라면 검색 전에 '공항 이름으로 전체 지역 검색' 버튼을 제공한다. 다른 도시의 공항이 현재 일정 주변 범위에서 제외될 수 있음을 안내한다.
- 장소 이름, 주소, 위도, 경도, 날짜, 선택 시간, 카테고리, 메모 저장.
- 지도 클릭으로 직접 위치 선택. 좌표 및 시간 없이 저장 가능.
- 일정 수정·삭제·같은 날짜 내 위/아래 순서 변경. 수정 중 날짜 이동 가능.

### 저장 및 복구
- 버전 1 스키마로 localStorage에 저장. JSON 백업 다운로드와 검증 후 복원.
- 복원은 전체 교체임을 확인한다. 손상 데이터 자동 덮어쓰기 금지. 저장 실패 안내.

## 장소 보관함
- 여행 배너 아래 '여행 일정'과 '장소 보관함' 보기 전환을 제공한다. 보관함은 여행별로 분리되며 후보 수를 표시한다. 두 보기에서 지도 인스턴스를 재사용한다.
- 날짜 미정 후보를 장소 검색/지도 클릭/직접 입력으로 추가하고 이름·주소·좌표·카테고리·메모를 저장한다. 날짜와 시간은 후보에 저장하지 않으며 좌표 없이도 저장할 수 있다. 기존 일정 편집기의 지도/검색 조건·제한·오류 처리·한국어 표기를 공유한다.
- 후보 목록 번호와 지도 핀 번호를 연결하고, 카드/핀 선택 시 지도 이동·카드 스크롤·상세 강조를 제공한다. 후보 번호는 방문 순서가 아니므로 연결선을 표시하지 않는다. 전체 장소 보기와 후보 수정·삭제를 제공한다.
- 후보 상세에서 여행 기간 안의 날짜를 선택해 '일정으로 이동'한다. 선택 날짜의 마지막 일정에 시간 미정으로 추가하고 후보는 보관함에서 제거한다. 같은 ID와 모든 장소 정보를 유지하고, 중복 이동/잘못된 날짜 이동은 막는다. 이동 후 해당 날짜의 일정 보기를 연다.
- Trip.savedPlaces는 선택적 배열로 추가한다. 기존 version 1 데이터와 백업에서 누락된 배열은 화면에서 빈 보관함으로 취급한다. 새 데이터는 localStorage와 JSON 백업에 포함하며 복원 시 필드/좌표/중복 ID를 검증한다. 여행 수정 시 후보를 보존한다.

## 여행별 준비물

- 공유 여행은 항목마다 내 완료 체크 하나를 보여주고 두 계정의 완료 수를 표시한다. 같은 항목을 두 사람이 동시에 체크해도 최신 서버 상태에 각자의 변경을 적용한다. 기존 공유 체크는 어느 계정이 완료했는지 알 수 없으므로 재확인을 안내한다. 기기 여행은 기존 완료 체크를 사용한다.
- 여행 배너 아래 '준비물' 탭을 제공하고 완료/전체 개수를 표시한다. 준비물 화면에서는 지도를 숨기며 일정/보관함으로 돌아올 때 기존 지도 인스턴스를 재사용한다.
- 준비물 이름 추가, 이름 수정/취소, 삭제 확인, 완료 체크/해제를 지원한다. 체크 여부와 항목 순서를 유지하며 완료한 항목은 취소선으로 구분한다. 공백뿐인 이름은 저장하지 않고 입력 이름은 최대 150자다.
- 완료 개수와 진행률을 표시하고 빈 목록 안내를 제공한다. 모바일에서 체크 영역과 수정·삭제 버튼을 터치하기 쉽게 배치한다. 광고/추천 항목이나 외부 API는 사용하지 않는다.
- Trip.packingItems는 선택적 배열이며 각 항목은 id/name/completed를 저장한다. 구형 데이터에 필드가 없으면 빈 목록으로 처리하고 기존 version 1 백업과 호환한다. 복원 시 형식·중복 ID·완료 값 타입을 검증한다. localStorage/JSON 백업 및 여행 편집 시 준비물을 보존한다. 여행 간 목록과 완료 상태는 분리된다.

## 지도 및 검색 제약

- 일정 카드에는 순번 아래에 시간을 표시한다. 일정의 좌표 주변 위키백과 문서에서 이름이 일치하고 위키미디어 공용에서 재사용 조건을 확인한 사진만 왼쪽에 자동 표시한다. 사진에 저작자와 라이선스를 표시하고 일치 항목이 없으면 생략한다. 기존에 저장한 사진 URL은 호환을 위해 유지한다. 브라우저 뒤로가기는 편집창을 먼저 닫고 여행 상세에서는 여행 목록으로 돌아간다.

- 일정과 보관함은 사용자가 붙여넣은 Google 지도 공유 링크를 선택 사항으로 저장한다. 카드 상세에서 링크를 열 수 있다. 링크는 기존 여행 백업·공유 데이터에 포함된다. 변환 서버가 설정된 경우 Google 지도 짧은 링크에서 이름과 명시된 장소 좌표를 채운다. 사용자가 이미 입력한 이름과 위치는 보존하며 변환 실패 시 직접 입력할 수 있다.

- 일정과 보관함에서 전체 지역 검색은 여행지 주변 결과를 우선하되 반경으로 제외하지 않는다. 장소 이름과 주소를 함께 검색한 후 주소만 따로 검색할 수 있다. 주소 결과는 장소 이름을 유지하며 지도에서 위치를 확인한다.
- 검색 서비스에 장소가 없을 때 Google 지도 검색 링크를 열고 호랑나비 지도에서 직접 선택하거나, 위도와 경도를 입력해 핀을 지정할 수 있다. 좌표 입력은 외부 API를 호출하지 않는다.
- 사용자가 Google Maps 전환을 선택했다. `VITE_GOOGLE_MAPS_API_KEY` 설정 시 Maps JavaScript API를 한국어(`language=ko`, `region=KR`)로 로드한다. Advanced Markers로 번호 핀을 표시하며 배포 시 자체 Map ID를 사용한다. 키가 없으면 기존 MapLibre GL JS + OpenFreeMap으로 실행한다.
- Google 지도에서는 Google 로고/저작권을 유지하고 한국어 표시를 요청한다. 실제 번역 범위는 Google 데이터에 의존한다. 무료 지도에서는 OpenStreetMap 출처를 유지하며 한국어 → 영어 → 기존 이름 순으로 표시한다. 도로 번호·건물 번호 등 지명 외 라벨은 그대로 유지한다.
- Photon 공용 데모 API를 이용한다. 버튼 제출만 요청, 최소 2초 간격, 동시 요청 방지, 세션 캐시(최대 100개), 12초 타임아웃. 결과 없음/네트워크/서버 오류 안내.
- 공용 서버의 안정성은 보장되지 않는다. 한국어 검색 결과가 적으면 현지어/영문과 도시를 함께 입력한다. 검색은 전 세계 검색이다.
- 좌표 없는 입력 및 편집은 외부 지도·검색 서버 상태와 독립적으로 동작한다.
- Google Places/Routes/Street View는 호출하지 않는다. 장소 검색은 Photon을 유지한다. 과금은 지도 로드 기준이고 무료량 안에서 운영하는 것을 목표로 하며, 항상 무료라고 보장하지 않는다. 설정과 비용 안내는 `docs/GOOGLE_MAPS_SETUP.md`를 따른다. 유료 경로 계산, 이동 시간 추정, 자동 최적 경로는 포함하지 않는다.

## 후속 개발
1. 장소 보관함 확장: 일정에서 보관함으로 되돌리기, 후보 정렬/필터 등은 후속 범위.
2. 준비물 확장: 분류/담당자/공통 템플릿은 후속 범위이며 현재 목록은 사용자가 직접 구성한다.
3. Firebase Authentication/Firestore: 허용된 두 계정만 접근하는 규칙, 실시간 공동 편집 및 충돌 정책. 무료 할당량 확인 후 도입.
4. PWA 설치, 캐시 갱신 정책 및 오프라인 사용 안내.

## 배포 및 개인정보
GitHub Pages에 공개 배포했다: https://ksy980324.github.io/horangnabi-v2/ . 정적 파일 공개와 여행 데이터 공유는 별개이며, MVP 데이터는 각 브라우저에만 존재한다. 현재 앱 소스와 UI는 공개이며 두 계정 인증은 후속이다. 실제 여행 데이터를 소스에 커밋하지 않는다. 외부 서버에는 지도 타일 요청 및 사용자가 제출한 장소 검색어가 전달된다.

- v2 폴더 내용을 별도 저장소의 최상위에 둔다. 상위 기존 앱은 변경/업로드하지 않는다. GitHub Actions에서 main push 또는 수동 실행으로 설치→타입 검사→테스트→빌드→dist 업로드→Pages 배포를 수행한다.
- configure-pages의 base_path에 맞춰 PAGES_BASE_PATH를 빌드 환경에 지정한다. 로컬 기본 base는 상대 경로를 유지한다. 앱은 클라이언트 내 상태로 화면을 전환하므로 별도 서버 경로 재작성은 필요하지 않다.
- GitHub Actions Secret GOOGLE_MAPS_API_KEY와 Variable GOOGLE_MAP_ID를 빌드 시 VITE 환경 변수로 전달한다. 배포 시 누락/예시 키/DEMO_MAP_ID는 안내 후 중단한다. 값 자체를 로그에 출력하지 않으며 브라우저 키의 유효성/도메인 허용은 별도 확인한다. 로컬 키 없는 무료 지도 실행은 유지한다.
- .env.local을 포함한 환경 파일, node_modules, dist, 앱 JSON 백업은 커밋에서 제외한다. 키는 빌드된 브라우저 코드에서 보일 수 있으므로 실제 호스트에 대한 웹사이트 제한과 Maps JavaScript API 제한을 유지한다. 경로가 생략되는 referrer를 고려해 GitHub Pages 호스트를 허용한다.
- 새 배포 주소에는 기존 localStorage 데이터가 자동 이전되지 않는다. JSON 백업/복원으로 가져오며 동기화는 Firebase 단계에서 구현한다. 실행 절차와 공개 범위는 docs/GITHUB_PAGES_SETUP.md에 기록한다.
